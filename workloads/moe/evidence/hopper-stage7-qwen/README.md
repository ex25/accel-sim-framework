## 主要修复与已知边界

- WGMMA读取准备移到寄存器收集完成处，使用已有有界collector，完整汇合后进入执行槽；读取服务、累加依赖、计算占用和写回等待保留。
- Hopper整数乘加与shuffle按已有资源分流；共享/global向量完整宽度、L1真命中写回仲裁补齐，原数值不改。
- 简化DRAM按请求字节服务，目标H100 HBM3时钟改为2619MHz；peer L2更新保留dirty eviction、端口及背压，补齐在途请求结束判断。
- 冷启动API长空档、硬件精细端口/缓存拓扑仍未完整建模；极小L2的peer进度失败保留，默认H100配置的完整运行已完成。

## 原始证据与复核方式

- [Stage7实际验收](../../../../.codex/execute/validation/stage-7/README.md)保存范围和历史状态。
- 原始完整回归：`workloads/moe/runs/hopper-stage-7/ordinary-fix-20261115/combined-full-20261115/`。各`full/<case>/<case>/`保存stdout、完整输出、run.json和event-timing.json，`analysis-20261116/`保存旧/新逐核及E2E。
- 原驱动full-state.json的failed来自摘要脚本假定每核一块累计统计；128/4096已离线恢复检查，8192另有event边界失败。原失败及恢复记录未覆盖，不把failed直接当作模拟/数值失败。
- event单行修复：`workloads/moe/runs/hopper-stage-7/event-cycle-fix-20261117/`。本附件保存原探针[event-cycle-probe.cu](event-cycle-probe.cu)及[观测脚本](observe-event-cycles.py)，观测脚本绑定该源码版本的调试行号。
- 本轮独立核查直接解码BF16参考、遍历所有保存输出，逐项核对冻结输入/程序/实际库/配置散列，从SIM_KERNEL重算所有调用并匹配30个硬件样本；复算已有读取阶段trace和event新旧观测，未运行被测程序。

大日志、运行库与张量留本地runs，不随本附件提交。
