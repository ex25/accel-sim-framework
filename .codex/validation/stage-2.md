## 本阶段通过意味着什么

三条普通cp.async指令能搬入真实数据、按每线程的提交组正确等待，并通过缓存/内存模型计时；Qwen64/128和Mixtral/128的独立gating得到正确矩阵输出。两个代表通过不等于九例完整前向已通过。

拟把测试放 `workloads/moe/tests/hopper/stage-2/`，结果放 `workloads/moe/runs/hopper-stage-2/`；本轮没有创建测试代码或运行结果。不能修改冻结PTX删掉wait、替换成同步load/store，或用host算好的矩阵代替内核输出。

| 顺序 | 必要测试 | 要证明什么 |
| --- | --- | --- |
| 1 | 完整16B、零源、predicate=false | 三种行为不同，源和目的分别正确 |
| 2 | 空组、逐lane归组、wait0/2/4/6 | 等待按提交序号，而非只数还剩几个请求 |
| 3 | 同PC多轮与shared缓冲轮换 | 返回匹配本次操作，读者不读到上轮数据 |
| 4 | 延迟变化和独立计算重叠 | 等待来自真实完成事件，同时保留异步能力 |
| 5 | 两个真实gating及受影响回归 | 原参数/布局/FMA组合正确，主要时间和流量合理 |

## 1. 单组拷贝：完整读取、零填和不执行分别检查

**对应实现：[解析与发起](../plans/stage-2.md#copy)、[返回交付](../plans/stage-2.md#completion)。** 使用一个CTA、一个warp。每lane有16B对齐且互不重叠的global源和shared目的。源第j字节为 `(17*lane+j)%256`，shared初始字节为 `0xa5`；先用合法CTA同步完成初始化，再发copy。

按下面三类分配lane，然后所有lane执行commit→wait0→必要的 `bar.sync`，读取自己的16B并写回输出：

| lane | 动作 | 16B目的预期 | global请求预期 |
| --- | --- | --- | --- |
| 0～15 | predicate=true，src_size=16 | 与该lane源逐字节相同 | 生成这16个lane的有效读取，合并后事务数由模型决定 |
| 16～23 | predicate=true，src_size=0 | 全部为0 | 不读取这些lane的global源 |
| 24～31 | predicate=false | 保持`a5` | 不生成请求，也不执行零填 |

另用一次全warp src_size=0的启动，检查没有任何global读取仍能交付零填、commit/wait正常结束。这覆盖“没有返回事件”分支，防止等待永远不结束或直接跳过写零。

保留源、目的、有效lane mask、UID、请求数和输出。copy的目的地址寄存器、global地址寄存器、src_size寄存器均要列入读取依赖；没有普通输出寄存器。可让三者由紧邻前序整数计算产生，核对依赖和实际地址，不另建复杂框架。

数据顺序证据记录：`issue → 请求完成 → shared交付 → 组完成 → wait放行 → 消费`。对有请求的UID，交付不能早于最后一个相关请求返回。允许计划规定的统一交付粒度，不强求每lane在自己的最早返回周期立即可见。

当前源长度只用0/16，1～15B不作为阶段阻塞项。若实现自然支持，可附一个廉价的部分源检查，但不能把它升级为必须完成的组合测试矩阵。

## 2. commit/wait：既检查数据，也直接检查等待边界

**对应实现：[本线程组状态](../plans/stage-2.md#groups)。** N表示允许尚未完成的**最近N个已提交组**，不是允许任意N个旧组未完成。用下列两层证据区分算法正确和真实接线正确。

### 小型状态检查：只验证难以靠随机内存返回稳定触发的次序

通过实现的组状态/完成接口提交0～7八组，使用人工完成通知安排返回顺序；这是组件测试，不是PTX周期运行。每组一份copy，shared数据交付后才允许完成通知生效。

1. 提交八组后执行wait6。组0和1都未完成时应等待。
2. 先完成组2～7。虽然此时仅剩两个未完成组，wait6仍必须等待0和1；不能因“未完成数≤6”就放行。
3. 完成0但不完成1，继续等待；完成1后释放。另一次安排先完成0/1、保留2～7未完成，wait6应能释放，证明没有被错写成wait0。
4. 对N=2/4各用C=N+2组重复同一截止检查，旧组同样为0、1；N=0要求所有已提交组完成。测试预期直接来自这些固定序号，不调用模拟器的截止计算函数生成预期。
5. 当前未提交组有copy时，先前已提交组都完成的wait0不应等待它；之后commit→wait0才等待该copy。只检查状态，不在程序里提前读取未提交数据。

该组件检查只回答边界，不可单独作为“cp.async已通过”。下一层必须跑真实PTX和LSU返回。

### PTX周期运行：真实分组、空组和lane归属

用循环连续提交C=N+2组，分别取N=0/2/4/6；每组使用独立shared槽位，源字节按组号和lane编号编码。C最大8，避免为了测试制造不必要的超长未完成队列。

- 执行wait N后仅消费已被保证完成的前两组；随后wait0再消费所有组。比较全输出，并核对日志中的截止序号和放行时刻。不要求真实内存恰好按组件测试的人工次序返回。
- 插入一次没有copy的commit，确认它也占一个提交序号且立即完成。后续截止仍按提交次序，不能因清理完成组而变化。
- 同一warp内部分lane的copy谓词为假，所有lane照常commit；确认这些lane的组不会因没有请求而永久等待，也不会被别人的copy计数污染。
- 额外让高半warp在合法分支中先提交一个空组，再汇合执行同一条copy/commit/wait0。高低半组号不同，但每lane结果正确。它专门检查“每线程组”是否被误写成一个全warp组号，不需要穷举所有分歧形式。

完成记录至少有CTA、warp/lane、动态UID、组序号、commit、数据交付、wait截止和释放周期。组件检查与PTX运行分别标明，不把人工完成通知说成真实DRAM返回。

## 3. 缓冲轮换：只在合法同步后读取和覆盖

**对应实现：[shared复用](../plans/stage-2.md#reuse)。** tile在这里就是一小块矩阵数据；测试用带轮次标记的整数代替矩阵值，让“读到上轮”容易发现。

准备两个shared槽位A/B、至少四轮global图案，按轮次交替使用槽位。每lane每轮写入的4个32位值可取 `10000*round + 100*lane + j`，j=0～3。循环体中copy位于同一个PTX PC。

1. 预取下一轮槽位时，当前轮只消费已经wait完成、并经过所需CTA同步的槽位。
2. 在某个槽位被下一次copy覆盖前，先保证所有读它的线程已完成读取；保留原程序所需barrier。每轮消费结果单独写出，不只比较最终总和，避免两轮错误互相抵消。
3. 至少一次由另一lane读取已完成copy的数据，证明wait和线程间屏障的组合有效；不把wait当作其它线程也已到达的证据。
4. 用两CTA、相同shared偏移但不同源图案再运行一次，确认返回写到发起CTA的shared。无需加入cluster或远程shared。

同时观察同一PC产生的不同UID。加入一小段“同PC、同global源地址、不同shared槽位”的连续组，保证多次copy可同时未完成；完成记录按UID逐一核销，不能用PC+lane0地址提前消掉另一份copy。此项主要看身份和时序，因为相同源内容未必让最终数值暴露错配。

通过条件：各轮、各CTA全部输出精确；每次合法消费在对应交付和同步之后；结束时本次copy记录全部完成并释放。这里不通过删同步来人为制造数据竞争，也不要求竞争程序必然读到旧值。

## 4. 时间行为：等待能变长，独立工作仍能推进

复用上面copy微测，采用一份基础配置和一份仅增加已有内存延迟参数的微测配置；保存具体参数差异，确认所测请求确实到达被修改的内存层级。不能请求命中L2却用改变DRAM延迟得出结论。

- 依赖检查：立即wait0后消费时，增加实际访问层级的延迟应推迟copy完成及消费者开始。若不变，先检查缓存命中和是否真正等待，不随意调其它参数掩盖问题。
- 非阻塞检查：copy发起与wait之间放有可见输出的独立整数/FMA计算，另外一个warp执行独立工作。日志应能观察到未完成copy存在时这些指令仍推进；不能因wait挂起整个SM或阻止LSU返回。
- 流水检查：用合法单缓冲与双缓冲两版完成同样的copy和计算。两版都正确，双缓冲至少在所选足量工作中出现搬运与计算交叠；不规定所有规模都快固定百分比。若没有交叠，解释具体瓶颈，再用最小必要工作量确认异步路径。
- 流量检查：`.cg`请求走全局缓存策略；src_size=0或predicate=false不产生global读取。比较有效访问字节、合并事务及L2/DRAM计数三层口径，不把它们强行要求成同一个数。

记录统一交付粒度和尚未单独细化的异步shared写bank费用；它们是明确的模型近似。不能借这个近似省掉真实请求时间、组等待或shared消费者的既有bank模型。

## 5. 两个真实gating：先数值，再判断性能是否可比

### 原始调用条件

以下launch值按 `forward.bin` 的记录只读解码核实，未运行模拟器。三项grid/block/cluster均按x/y/z给出，最后一列为本次动态shared。矩阵记作 `Y[token,expert] = sum_k X[token,k] * W[expert,k]`，实际参数次序和存储布局仍要按原PTX绑定，不能靠这个数学记号猜地址。

| 用例、模块 | 逻辑矩阵规模 | grid / block / cluster | 动态shared |
| --- | --- | --- | ---: |
| Qwen64/128，71 | X为128×2048，W为64×2048，Y为128×64 | 8×1×1 / 128×1×1 / 1×1×1 | 24576B |
| Mixtral/128，2 | X为128×4096，W为8×4096，Y为128×8 | 4×1×1 / 64×1×1 / 1×1×1 | 24576B |

从原PTX和参数来源建立一张三指针绑定表，记录哪项指向X/W/Y、元素类型及行步长。模块71存在BF16读取后转换及FP32读取，模块2的对应输入读取为FP32；不能假设两个模块都接收两块BF16矩阵。所需前序转换可由阶段1真实转换或独立host预处理准备，报告写明采用哪种。

### 数值输入和预期

保留上述完整尺寸，用小整数构造可精确计算且非对称的矩阵，例如：

```text
X[t,k] = ((3*t + k) mod 7) - 3
W[e,k] = ((5*e + 2*k) mod 11) - 5
Y[t,e] = sum over k of X[t,k] * W[e,k]
```

这些值都可由当前输入浮点格式精确表示，乘积与累加范围也足够小，独立CPU整数累加即可得到精确参考，再转FP32比较全矩阵。不使用全部1、全0或只比较校验和，因为这些输入容易掩盖转置、错tile及漏计算。

运行顺序：模块71先验证wait0和混合输入类型；模块2再验证wait6/0多级预取。每例记录完整输出、失败元素数、最大差异、首次错误坐标和提交。人工整数数据要求精确相等，不能用20%时间目标或2%浮点容差放过它。随后使用冻结输入对应数据时，浮点比较沿已确认数值规则，并保留全输出差异；不改原容差。

### 性能参照和不能直接比较的情况

核对[现有性能材料](../../workloads/moe/docs/performance.md)中该case该次gating的ncu duration和流量，不拿整例kernel时间之和与单个gating比较。设备时间由该kernel周期和实际配置频率换算；host墙钟单列。

冻结完整运行在gating之前还有初始化和转换，这些操作会影响缓存。单模块入口的host拷贝、`perf_sim_memcpy`填L2行为或人工预热都不自动等价于真实前序：

- 能复现同一输入、原launch及可比缓存前序时，记录条件并计算该kernel时间相对差异，约20%作为初期目标；同时看L2/DRAM流量判断原因。
- 条件尚不可比时，只报告数值通过、时间/流量和已知差异；性能校准标为待完整前序复验。不得填“误差已达标”，也不靠调指令延迟抵消主机间隙或缓存条件差异。

模块61的wait2和模块99的wait4已在微测覆盖，但未运行这两个真实gating；后续九例验收仍需逐例覆盖。当前不要求为了凑覆盖率立即运行全部九个gating。

## 6. 受影响回归、运行成本与停止条件

若修改了共用LDGSTS完成/DEPBAR路径，运行已有可用的最小SASS拷贝/等待trace，检查组释放、请求计数及周期；用修改前同配置结果作参照。若共用访问生成或返回处理变化，补一组普通global load/store及shared消费。没有可运行trace时明确写未覆盖及原因，不能把组件测试改名为SASS运行验收。

每个真实gating保存 `/usr/bin/time -v` 和初始化/模拟/比较分段时间；关闭无必要的逐指令输出，记录实际构建方式。只为有数据支持的同类gating估算剩余运行成本，不用GPU微秒直接推算CPU模拟用时，也不把gating速度用于WGMMA预算。

三条指令的必要数据/分组/主要时间检查及两例数值通过后可以推进。性能条件不齐时具体列出待复验项；若存在提前消费、错误组释放、挂死或请求被当成零时间，必须先修。未使用变体、复杂部分源、非法重叠写及完整DMA模型不扩大进本阶段。
