# 阶段 3 验收：cluster、地址和资源

状态：未运行。[实现方案](../plans/stage-3.md)；[公共规则](README.md)。

## 覆盖对象

`cudaLaunchKernelExC`、cluster 特殊寄存器、`mapa.shared::cluster.u32`、cluster arrive/wait，以及已有 generic 地址转换和 CTA 资源计算。这里只证明身份、共同推进和存储生命周期；不提前给 TMA 或远端数据完成验收结论。

## 必要测试

| 测试 | 动作 | 正确结果与为什么需要 |
| --- | --- | --- |
| 两 CTA 身份 | 1×2×1 cluster，两个 CTA 回写 grid 坐标、cluster 内坐标和 rank | y=0/1 对应 rank0/1，同组 cluster 身份相同；否则后续通知会发给错误 CTA |
| shared 对象与 mapa | 至少两个 cluster 在相同 shared offset 写不同标记；组件检查映射地址解析到哪个对象 | 保留偏移但目标 rank 改变，跨 cluster 不串；不为测试增加 workload 未用的远端 load/store 指令 |
| 实际资源和大地址 | 用384线程、215040B动态shared及核实物理寄存器额度，启动66×2×1 grid；在合法高偏移写读 | 当前两 CTA 跨 SM，全部132 SM范围正确；覆盖 SM≥80、shared>96KiB，cvta 正反转换与 local/global 不混 |
| 延迟到达 | 一 CTA 做有限合法计算后才到 cluster barrier，另一 CTA 先等待；运行多组 | 同伴仍能被调度并完成，不能只驻留每组一半导致相互等；记录等待和同伴发射顺序 |
| 生命周期 | 连续运行多组/两次 launch，在本组合法退出前检查映射及后续复用 | 活跃对象不被下一组覆盖；本阶段按已支持同步检查，异步在途访问等阶段5联测 |

高地址访问必须在实际分配内；不做故意越界的恢复测试。relaxed arrive/wait 的通过仅说明参与和同步推进，不能据此声称任意 shared 写已向异步操作发布。

## 资源记录必须分开

记录 PTX 静态0B、launch动态215040B、占用开销1024B、H100总分配216064B，以及每SM233472B容量；对模型采用的保留/对齐方式说明依据。许可上限不计作实际分配。记录寄存器物理额度64512/CTA，不把大量PTX虚拟寄存器声明直接用于占用。

当前资源限制每 SM 一个此类 CTA；一个普通小 CTA 测试应仍可按资源允许多驻留，防止把此内核特例写成 Hopper 全局规则。

## SASS 回归与停止

对修改的调度/地址共用部分检查普通 CTA 行为和已有 cluster metadata 使用。跨 SM 通信成本此时只核对接入位置；TMA 字节和完整完成时序由阶段5验证。不扩多卡、任意 cluster 形状或完整 GPC 拓扑。
