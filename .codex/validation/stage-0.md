# 阶段 0 验收：加载、参数与普通启动

状态：未运行，以下均为通过条件。[实现方案](../plans/stage-0.md)；[公共记录规则](README.md)。

## 验收要回答什么

小程序能否使用模拟器 libcudart，正确选择 PTX entry、传参并按本次 shared 配置执行？这里验收加载/接口和现有基础指令，不宣称 Hopper 完整程序已支持。

## 必要测试

| 测试 | 如何准备和执行 | 预期与覆盖对象 |
| --- | --- | --- |
| 构建和运行身份 | 按 AGENTS.md debug 构建；运行写回线程号的小程序，记录动态库加载及 PTX 周期配置 | 实际进入 PTX 功能+周期路径，输出线程号正确，设备周期有增长；覆盖基本 `mov/ld.param/st/ret` |
| 两模块交替 | 两 fatbinary 分别提供唯一 entry `write_a/write_b`、唯一 global/constant 标记；依次调用 A→B→A，预期 11→22→11。分别采用直接 API 与编译器入口；包含 sm_90/sm_90a 目标 | 调用与资源归属不串；提取/ptxas 保留实际目标。只有测试失败才修改模块管理，不要求支持未出现的重名符号 |
| 64B 参数布局 | 传一个 `.param .align 64 .b8` 结构体，前后放大小不同标量；设备逐字段回写不同标记 | 字段和参数偏移精确正确，不能仅看 parser 不报错；覆盖声明、`ld.param` 和参数绑定 |
| launch/shared 不串 | 同一函数连续不同 grid/block 和动态 shared；先设较高 opt-in，实际两次申请不同字节，各自写读合法末端区域 | 实际分配随 launch，许可上限不被当成每次分配；回写线程块标记、资源占用和 shared 正确。大于96KiB的完整地址压力留阶段3 |
| 数据顺序与失败出口 | H2D→kernel→D2H，另包含当前需要的 D2D/memset；外部 `.noreturn __assertfail` 正常加载，再用一个测试明确触发失败 | 正常路径数据/顺序正确，失败路径非零退出并报告，不能静默成功；不做异常输入穷举 |

测试程序使用有定义的 CUDA/PTX 参数。不要靠越界访问验证分配，不给冻结二进制打补丁跳过未支持能力。两模块测试的标记名称独立，避免引入当前 workload 没有的链接规则需求。

## 时间与资源怎么检查

记录实际 kernel 起止周期和驻留数；同一程序增加合法循环/工作量后周期应合理增加，不要求微测精确匹配 H100。确认显式复制是否仅更新数据/L2；没有 DMA 周期模型就标注未计，不从函数名推断。

从本阶段第一次运行开始使用 `/usr/bin/time -v`；单列装载/初始化与设备模拟部分的墙钟。这里取得的是工具链与小程序基线，不外推大专家 GEMM。

## 交付与停止

上述必要测试通过，保存可复用单模块入口和记录模板即可进入阶段 1。若多模块已正常工作，不再重构全局符号表。SASS 本身不走 CUDA 参数加载；仅修改共用资源计算时回归普通 CTA 驻留，不为本阶段另建大 trace 套件。
