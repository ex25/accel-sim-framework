# 阶段 1 验收：基础数值和真实普通内核

状态：未运行。[实现方案及完整指令清单](../plans/stage-1.md)；[公共规则](README.md)。

## 为什么测这些

路由结果决定 token 交给哪个专家；索引或计数错一点就会改变后续全部矩阵输入。先用可算清的小值验基础，再执行少量真实 entry，避免等专家 GEMM 完整实现后才定位普通指令错误。

## 最小测试与预期

| 指令组 | 输入/动作 | 通过证据 |
| --- | --- | --- |
| 三种 BF16 转换 | 正负有限值、零、可精确表示值、舍入中点两侧；打包两半用不同值 | `cvt.f32.bf16`、两种 rn 输出位模式正确；预期按独立位计算产生，不能调用模拟器转换函数 |
| 三种 shfl.sync 与 ballot | 使用完整 mask 及冻结 PTX 的合法部分 mask；源 lane 放唯一整数，包含实际索引和分段形式 | 每 lane 输出及 predicate/ballot 精确；未参与线程不被算入；不测试未定义源并要求补零 |
| redux/elect/lanemask/bfind | 参与 lane 放小整数；elect 检查 leader 输出与 predicate；lanemask 检查 lane0/31，bfind 检查零和高位 | 和正确、恰好一个 leader、参与者对 leader 一致；位模式符合说明，不要求 leader 与硬件特定选择相同 |
| bar.warp.sync/shared | 参与线程写各自 shared，合法同步后由同组参与者读取；另一组不依赖此屏障继续工作 | 同步后的值正确，不把部分 warp 屏障变成整个 CTA 等待 |
| 三种带 eviction hint 的 load | 有效地址/不同数据，核对读取值和请求 | 真实读取发生、类型宽度正确；细微缓存替换差异不作为本阶段阻塞 |

未使用的特殊浮点组合、非法参与 mask 和任意 warp 分歧不扩测。若真实内核出现非有限值或合法参与者无法汇合，必须定位，不能以暂缓为由跳过。

## 真实消费者怎么测

选择模块 0/70 的转换和模块 3/4、10/14 中能覆盖路由/映射的代表，加一个 SwiGLU 代表（候选模块82）。按原 entry 参数和写死维度准备合法输入；不用全部 110 模块各做单测。

- 转换逐元素比位模式；top-k 用无歧义排名输入检查专家编号和顺序。
- 计数/映射用已知 token→专家表，CPU 分别统计每专家数量和位置；计数之和、每项索引与完整结果精确比较。
- SwiGLU 用有限小值，独立 CPU 数学计算预期；浮点采用对应容差，不能用离散索引规则放宽计数。

这些真实模块未用到普通 cp.async 就可测试；不能把冻结完整程序尚不可启动误记为这些 entry 已失败。

## 时序、SASS 回归与停止

用有依赖的 shuffle 链确认第六项 SHFL latency/initiation 生效；合法工作量增加时周期/访问量合理增长。只检查改动影响的普通 load/store、shared atomic、bar.sync 与算术路径。相同的共用流水若影响 SASS，补对应最小回归，不回归无关 opcode。

首个真实普通内核记录初始化、模拟、比较墙钟及 RSS。它只能估计相似普通内核成本；WGMMA 仍未知。必要基础测试和一组真实转换/路由/重排通过即可推进，专家专用项在其消费者前补齐。
