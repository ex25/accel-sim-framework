# 阶段 1 验收：检查数值、参与线程与真实路由结果

状态：未构建、未运行。下文是未来执行要求，不是通过报告。配套：[阶段 1 实现方案](../plans/stage-1.md)；运行身份、构建和记录复用[阶段 0 入口](stage-0.md#runner)。

## 本阶段通过意味着什么

真实转换、路由、计数/重排内核能独立运行，数值和索引正确，相关指令有有效时间模型。它不证明 gating、专家矩阵或完整前向已经通过。专家专用指令若后做，必须单列尚未验证项，不能随首批普通内核一并标成完成。

拟在 `workloads/moe/tests/hopper/stage-1/` 放本阶段测试，结果放 `workloads/moe/runs/hopper-stage-1/`；本轮没有创建这些程序或运行目录。沿用阶段0的host注册/启动入口，选择被测模块并输出结果，不改冻结PTX或启动器。

| 顺序 | 必要检查 | 能区别的错误 |
| --- | --- | --- |
| 1 | BF16往返、舍入和打包 | 误当FP16、截断代替舍入、两个源顺序反了 |
| 2 | shfl/ballot/redux/elect的值、mask、predicate | 用计数代替lane编号、漏mask、提前覆盖源、双输出遗漏 |
| 3 | warp屏障及位操作/load提示 | 屏障范围扩大、错误位图/位查找、读取宽度改变 |
| 4 | 真实转换、top-k/排序、计数/映射、SwiGLU | 微测正确但真实参数、布局或已有指令仍不正确 |
| 5 | 依赖/吞吐、受影响回归、墙钟/RSS | 只算值没有正确计时，或无法估计下一阶段运行成本 |

## 1. BF16：先固定原始位模式，再比较转换结果

**对应实现：[数值转换](../plans/stage-1.md#numeric)。** 输入由主机按整数位模式构造；预期由独立测试代码或下表提供，不能调用模拟器里的转换函数。使用真实PTX的 `.b16/.b32` 保存格式，并让输出写回global供主机检查。

### 单值转换

| FP32输入位模式 | `cvt.rn.bf16.f32`预期 | 检查原因 |
| --- | --- | --- |
| `00000000`、`80000000` | `0000`、`8000` | 正负零保留 |
| `3f800000`、`c0000000` | `3f80`、`c000` | 1与-2准确转换 |
| `3f807fff` | `3f80` | 舍入中点下方 |
| `3f808000` | `3f80` | 中点，保留位偶数 |
| `3f808001` | `3f81` | 舍入中点上方 |
| `3f818000` | `3f82` | 中点，保留位奇数时进位 |
| `7f800000`、`ff800000` | `7f80`、`ff80` | 无穷不被普通舍入破坏 |

对 `cvt.f32.bf16`，输入 `0000、8000、3f80、c000、0001`，分别得到 `00000000、80000000、3f800000、c0000000、00010000`。最后一项只检查无 `.ftz` 的位扩展，不扩成全套非规格数运算测试。

增加一个NaN类别检查，按该转换的PTX规则核对输出仍为NaN；不把完整前向“所有数值有限”的规则用于这条专门输入NaN的微测，也不要求未规定的NaN载荷完全保留。

### 两值打包与依赖

执行 `cvt.rn.bf16x2.f32 d,1.0,-2.0`，预期32位结果为 `0x3f80c000`；交换源后应为 `0xc0003f80`。再用上表两个不同舍入中点检查两个源各自舍入。

让第二个源由前一条有依赖的FP32计算产生；检查预解码列出了两个源，消费 d 的指令等到结果就绪。这样同时证明“读取两个值”和“等待两个输入”，不只验证常量折叠后的结果。编译后核对测试PTX确实包含目标指令。

通过条件：规定的位模式逐项精确一致，目的寄存器宽度和打包次序正确；不使用2%数值容差放过转换错误。

## 2. warp协作：用可手算值检查真实lane和mask

**对应实现：[集合操作](../plans/stage-1.md#collectives)。** 先用一个warp，再在同一CTA用两个warp运行不同输入，检查状态没有混用。各线程记录数据结果以及用 `selp` 转成0/1的predicate结果，测试比较的是逻辑真假，不依赖模拟器内部predicate编码。

### shuffle三种形式

令lane i原始输入为 `100+i`。全部参与时采用 `0xffffffff`；部分参与时让同一warp只有lane16～31执行，使用 `0xffff0000`，低半warp走不含这条指令的分支。

| 指令参数 | 精确预期 |
| --- | --- |
| bfly：b=16，c=31，全mask | lane i得到 `100+(i xor 16)`，predicate全真 |
| up：b=2，c=0，全mask | lane0/1保持100/101且predicate假；lane i≥2得到 `100+i-2`且predicate真 |
| idx：b=3，c=`0x100f`，高半mask | 所有参与者读取lane19，得到119且predicate真；低半warp不写此输出 |
| idx：b=7，c=3，全mask | 索引超过clamp，各lane保持自己的输入且predicate假；不访问一个未参与源来制造未定义测试 |

bfly增加一次 `d=a` 原地版本，预期与不同目的寄存器版本相同。这是针对当前逐lane立即写回结构的必要检查，不是扩大随机组合。另一warp把输入换成 `1000+i`，两个warp各自输出，不能互相串值。

### ballot、redux、elect

- ballot：全mask下 predicate 为“lane编号为偶数”，结果为 `0x55555555`；仅高半参与时为 `0x55550000`。同样输入换成 `!predicate`，全mask预期 `0xaaaaaaaa`。随后按真实top-k形式，用第一次ballot的结果作为后一次指令的member mask，只让该mask内线程执行，检查第二次参与集合来自运行时寄存器。
- redux：全mask下输入 `i+1`，所有结果为528；高半mask下为392。再用输入 `i-16` 的全mask求和，结果为-16的32位表示，检查符号解释。不穷举溢出组合。
- elect：全mask和高半mask分别检查所有参与者报告同一个、属于mask的leader，且恰好一个predicate为真。连续两次相同mask得到相同leader；实现选最低lane时分别为0、16。再运行 `_|p` 数据丢弃形式，检查只有predicate写依赖。不能要求匹配某张GPU恰好选中的编号。

### 汇合与写回证据

最少保存一例的warp/lane、PC、member mask、实际到达集合、数据/predicate目的和完成周期。先验证上面的合法部分mask，以及真实top-k使用的运行时mask；不人为扩充任意分歧压力用例。

若真实合法路径发生分批到达，报告首次阻塞的指令、仍缺哪些lane及它们所在分支，再按方案补最小汇合支持。不能通过缩小member mask、把predicate为假的线程补成参与者或超时强制放行取得通过。单纯“进程没卡死”也不能代替输出比较。

## 3. warp屏障：正确读到同组写入，另一warp不必到达

**对应实现：[warp屏障](../plans/stage-1.md#warp-barrier)。** 用两个warp的CTA，shared区域互不重叠：

1. warp0的lane i写 `S[i]=100+i`，执行 `bar.warp.sync 0xffffffff`，再读取 `S[i xor 1]` 并输出，预期为 `100+(i xor 1)`。
2. warp1执行有限的独立算术并写一个完成标记，不执行这条warp屏障。warp0不能等待warp1到达；两者最终都结束。记录屏障等待集合，不能仅凭最终退出判断是否误等。
3. 部分mask版本只让warp0的lane16～31写自己的槽位、执行高半mask屏障并互读；其余线程不访问这些槽位。预期逐项精确，屏障只包含这16个线程。

检查参与者屏障前相关访存完成/可见的事件先于屏障放行，放行先于合法读取。不要删掉屏障后用数据竞争程序来要求“必须读到旧值”。这个测试不要求提前实现独立线程调度，也不测试其它warp偷读尚未同步的数据。

## 4. 位操作与带缓存提示的load

**对应实现：[位运算和提示](../plans/stage-1.md#bits-loads)。**

| 目标 | 输入与精确预期 | 额外观察 |
| --- | --- | --- |
| `%lanemask_le` | lane0/16/31分别为`00000001/0001ffff/ffffffff`；完整32lane按同一定义比较 | lane编号来自当前warp位置，不是CTA全局线程号 |
| `bfind.shiftamt.u32` | 0、1、8、`80000000`分别得到`ffffffff`、31、28、0 | 0正常结束；旧无shiftamt形式对同组输入应为`ffffffff`、0、3、31 |
| evict_first b32、evict_last b32 | 对齐global数组放不同32位整数，读回逐项相同 | 仍产生global读取和正常cache统计 |
| evict_first b8 | 字节`00、7f、80、ff`写到实际使用的较宽位寄存器 | 按b8读取并正确扩展，不能变成有符号数值转换或4B读取 |

带提示的load另留少量predicate为假的lane，输出保留初始化值，不能产生这些lane的访问。比较有效字节/地址，不要求每个lane对应一次DRAM事务：多个lane的访问会被合并，缓存也可能命中。逐出优先级未细化需如实记录，不因此阻塞当前数据通路。

## 5. 真实消费者：保留原entry、合法尺寸和参数布局

先从[模块清单](../../workloads/moe/artifacts/workloads.json)取得entry与指针参数位置，从对应 `forward.bin` 的launch记录取得参数尺寸、grid/block/shared。使用阶段0单模块入口，只分配该测试需要的缓冲区；结构体参数按原字节布局替换指针。输入由host构造，不能把未运行的前序内核输出当作已存在数据。

首轮优先Qwen64/128对应尺寸；跨用例共用模块按选定case的原参数调用。PTX可能写死维度，不能只把host数组缩小却保持原地址计算。以下表格给出测试目的和数据生成规则；执行报告还必须列出每个指针/标量参数的含义、实际尺寸及参考计算代码。

| 真实模块 | 怎样准备输入 | 比较什么 |
| --- | --- | --- |
| 70（或0）BF16→FP32转换 | 按原长度重复有限值位模式`0000/3f80/c000/3f81` | 全部输出位模式精确，与独立高16位扩展一致 |
| 3→4 top-k/排序 | 每token各专家分数用不重复整数构成排列；随token轮换最高分所在专家，保留case的E、k和张量布局 | 模块3比较选中集合及数值-编号配对，不能假定它已排序；模块4再检查原调用要求的排序方向和精确编号 |
| 77（或9）专家计数 | 人工构造合法token→专家分配，各token的k个专家不同；例如按 `(token+j)%E`，j从0到k-1 | 每专家计数精确等于CPU逐项统计，总和为tokens×k |
| 10及其必要后续映射，配一个14/80或重排代表 | 使用同一人工路由表；host独立生成其消费者要求的计数、偏移和合法填充，不猜参数含义 | 检查每个token在所属专家的行、各段范围与逆映射；重排数据用由token和列号生成的唯一标记，逐元素核对 |
| 82 SwiGLU | 保留原行宽，两个输入半区用不同的有限小值，包含0、±1及正负配对 | 独立CPU计算 `x/(1+exp(-x))*y`，按真实PTX的两半位置和输出类型比较；不能把输入两半互换 |

映射算法规定稳定顺序时，行号、前缀和、输出全部精确比较。若实际实现使用无序原子分配，先依据原语义确定允许的排列，再检查对应关系和数据逐项一致；不能硬指定CPU串行顺序，也不能只比较计数总和就放过丢失/重复token。

SwiGLU用独立CPU参考，包含真实BF16输入/输出舍入。先保存逐元素误差；本阶段沿用已确认的有限值和 `abs(error) <= 1e-5 + 0.02*abs(reference)` 上限，不放宽。若误差定位到单个转换，仍按位精确检查转换。离散索引和计数始终不使用浮点容差。

本表不要求立即单测所有变体；执行所选消费者必需的前置步骤即可，报告明确真正运行了哪些模块。未来阶段7还要以九例完整输出验收。

## 6. 时间、受影响回归与运行成本

**对应实现：[时序接入](../plans/stage-1.md#timing)。** 保存实际解码的执行单元、latency、initiation interval及配置来源，检查新指令没有零时间或误走CTA barrier。

- shuffle依赖链：构造32次和64次结果相依的shuffle，最终输出避免被删除；在测试配置中仅改变第六项latency，确认相关完成间隔/总周期随之增加。固定循环和launch开销单列，不要求总周期严格等于条数乘latency。
- shuffle吞吐：使用独立寄存器链和足够warp，仅改变第六项initiation；观察同执行单元接收相邻指令的间隔。若瓶颈在其它资源，增加到足以暴露该参数的有限工作量，不把“总时间不变”直接判功能失败。
- redux/elect及双目的：结果马上被下一条整数/分支指令消费，确认数据和predicate都被等待；若启用了单元1/4，记录其PTX侧配置确已生效。
- 受影响回归：BF16改动检查一组已有FP16/FP32或整数转换；shuffle共用代码检查原形式；bfind检查原返回方式。真实排序/映射已经覆盖的普通访存、atomic和CTA barrier不重复造同样测试。只有改动了共用SASS执行/完成代码才补对应trace回归；仅改PTX parser不跑整套SASS。

首个真实转换/路由内核开始记录初始化、模拟、比较墙钟及峰值RSS。保存真实尺寸、执行指令/周期数量，说明样本只适用于相似普通内核；不能据此保证九例或专家GEMM一周内跑完。真实时间比较仅在launch和缓存前序可比时进行，不拿微测与ncu的真实内核时间硬比。
