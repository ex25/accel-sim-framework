# 阶段 7 验收：真实专家、九例完整输出与性能

这是后续验收要求，当前九例全部未运行模拟验收。[实现方案](../plans/stage-7.md)；[公共规则](README.md)；[原性能基线和口径](../hopper-validation.md#性能比较的口径)。

## 开始正式九例前应有什么证据

开始前应确认阶段 0～6 当前消费者的必要功能/时序检查有记录，首次 TMA/WGMMA 联测和完整流水通过。原二进制能取得 tensor map 编码入口，完整注册 110 模块，并以真实 cluster/shared/参数启动。加载只是前置，不代表九例通过。

不使用 no-op 指令、CPU 直接代替专家输出或 SASS trace 驱动来取得正式结果。原程序、PTX、输入和数值容差保持冻结；诊断可临时导出数据，正式运行关闭额外抓取/同步。

## 1. 原专家模块的两个真实消费者

先分别测试模块 16 的 FC1 和 FC2，二者即使 entry 相同，也按参数、输入和输出形状分列。复用阶段 0 单模块入口，至少记录：1344B 参数原始字节与已解释字段表，grid/block/cluster/shared，物理寄存器资源，实际 A/B/C 的地址、步长、分组行数、tensor map。

### 数值预期如何得到

1. 用 Qwen64/128 对应合法形状准备可精确表示的小整数输入，原专家分组和行映射保持合法。逐专家独立计算矩阵乘加，再按原内核输出位置做 BF16 舍入；比较全部有效输出，填充区按内核合法写入范围检查。
2. FC1 和 FC2 各保存一次参数解释与参考过程，不能仅把第一次的输出指针换掉就假定第二次尺寸相同。参考实现不调用模拟器的 WGMMA/descriptor/swizzle 代码。
3. 完整前缀可执行后，如需验证真实数值，诊断运行捕获本次输入做 CPU 分块参考；逐元素要求有限并沿用 `abs(actual-ref) <= 1e-5 + 0.02*abs(ref)`，精确小整数样例还应精确匹配其独立预期。
4. 若小合法形状用于先定位，只标功能证据，不与冻结大调用计算硬件时间误差。真实尺寸调用的驻留和完整数据量仍由正式前向检查。

首个代表性尺寸专家调用完成时立即记录墙钟/RSS和实际逻辑 WGMMA 数，更新预算；不等九例结束。完整中间张量只保留定位所需的那份，不为每个 kernel 默认生成快照。

### 组合顺序必须有真实调用证据

从一次代表性调用提取少量动态事件，关联 kernel/cluster/rank/操作序号和 mbarrier 阶段：TMA 数据交付先于对应等待成功，WGMMA 合法读取输入，结果写回先于普通消费，TMA 输出 read 完成后才复用源，最后 global 确认参与内核完成。

这些是检查实现的要求，不是声称现有程序已经发生了旧 tile、提前覆盖或死锁。事件不符合时保存最小触发输入，修正所属阶段；不在阶段 7 加固定延迟、额外全局同步或模型名特判来遮盖。

## 2. 正式命令与记录

按[概览的环境配置](../hopper-validation.md#执行命令与记录位置)完成构建并设置 PTX 周期模式。下面从项目根的 `workloads/moe/` 执行，是未来命令，本轮没有运行：

```bash
mkdir -p runs
/usr/bin/time -v -o runs/qwen64-128.time.txt \
  python3 run.py --case qwen64 --tokens 128 --mode sim \
  --warmup 0 --iterations 1 --repeats 1 \
  --run-dir runs/qwen64-128
/usr/bin/time -v -o runs/qwen64-128.compare.time.txt \
  python3 compare.py artifacts/cases/qwen64-t128 runs/qwen64-128
```

`run.py` 要求目标 run-dir 尚不存在。重跑使用新的后缀目录，同时修改两个计时文件和 compare 路径，不覆盖先前失败证据。其它用例替换 case/tokens；保留各自目录，不在同一进程做预热。

正式前关闭 `MOE_TRACE_LAUNCHES` 和为定位加入的额外同步/全量导出。可以保留模拟器每 kernel 的必要摘要。确认运行目录内的 `gpgpusim.config`/互连配置确为本次需要的版本，PTX GMMA 等资源没有只停留在外层 trace.config。

| 记录 | 内容与用途 |
| --- | --- |
| 原 `run.json`、`stdout.log`、输出、`comparison.json` | 原二进制/输入 hash、实际 libcudart、运行退出、全量数值 |
| 提交和实际配置 | 外层/内层提交、未提交改动说明、工具链/构建方式、配置文件与 hash |
| 逐 kernel 摘要 | launch index、模块/entry、grid/block/cluster/shared、起止周期、频率、毫秒、主要工作量/字节 |
| 性能对照表 | 同调用 ncu 参照；4096 额外列 nsys；误差有正负号 |
| time 输出及分段时间戳 | 初始化、模拟和比较的墙钟，以及各进程峰值 RSS |

原 runner 已做的散列/库检查直接复用。缺少必要时间戳时在合适的模拟器统计入口补最小记录，不为这九例建立新的报告平台。

## 4. 数值和执行完成通过条件

`compare.py` 必须检查全部输出，所有值有限且逐元素满足 `abs(actual-ref) <= 1e-5 + 0.02*abs(ref)`。保存元素总数、失败数、逐位一致、最大绝对误差和相对 L2。20% 不用于数值，也不能只比较少数抽样行。

运行输出还须符合 manifest 的 22～24 次实际前向调用顺序；110 是加载集合，不应期待每例执行 110 次。FC1/FC2 均实际执行，内核最终完成未漏在途写回。

失败时，按已有信息先定位最早不一致处：整数路由/计数回阶段 1，普通异步复制回阶段 2，cluster/通知回阶段 3/4，descriptor/搬运回阶段 5，矩阵/累加/写回回阶段 6。只在需要时抓取相邻中间输入输出；硬件时间或计数接近不证明数值正确。

## 5. 设备时间比较：同一调用、同一范围

### 起止、单位与匹配

用前向的零起始 launch index 匹配参考，排除 setup_anchor；同时核对模块/entry 及 launch 形状。FC1/FC2 即使入口相同也不能合并。起点为 kernel 开始设备执行，终点为最后必要执行/访存完成，用同一全局周期基准：

```text
kernel_ms = (end_cycle - start_cycle) / core_MHz / 1000
sum_ms = Σ 本次前向的 kernel_ms
relative_error = sim_ms / reference_ms - 1
```

保留核内等待 CTA 资源、流水和访存的时间；排除核外主机提交等待与纯 launch 排队。各 SM 的 elapsed cycles 不相加，不能把所有 SM 的忙碌周期当一个 kernel 时长。

### 参照和结果怎么读

- 九例逐调用 ncu duration 与其总和是初期参照。保留采集的 replay/cache/clock 条件；不能称作自然运行完整设备跨度。
- 三个 4096 用例用 nsys 的 measured 样本再算相同内核总和和主要调用误差。保留它的预热/采集差异，不强行要求它与 ncu 数字相等，也不套统一“去采集开销”系数。
- 主要调用至少列 FC1、FC2、gating；再列占参考内核和 ≥5% 或解释主要差额的调用。有符号误差能看出相互抵消，例如 FC1 +40%、FC2 -35% 不能仅凭总和 +5% 宣称达标。
- `compare.py` 里的 `roi_time_relative_difference` 是独立 ROI 比较字段，native 侧可能来自含主机间隙的 CUDA event。它不是上述 kernel 总和误差；不要拿该字段填性能验收表。
- ROI、显式 CUDA copy、主机/launch 空档另外说明。缺自然运行完整设备时间时填“未补验”，不能填“DMA 实测为 0”。

### 大差额的最短定位顺序

先核对逻辑矩阵操作和有效/填充工作量，再比较 L2/DRAM 字节与组播目标写入量，再看等待/重叠，最后才调有证据的资源延迟/吞吐。每次修改写明原值、新值、解释的现象及受影响的调用；不按模型或 token 数拟合系数。

ncu L2 sector 按 32B 转换，DRAM 字节沿硬件层级比较；不能直接把 tensor map tile 字节或组播写两份的 shared 字节与 DRAM 画等号。记录采用的 TMA 服务近似、轮询近似、GMMA 初值等是否足以解释差额。

## 6. 模拟墙钟、RSS与剩余运行预算

本机运行一例可能很久，而模拟结果是 GPU 的毫秒数，两者单独汇报。初始化、模拟、输出比较分别计时；原 `/usr/bin/time -v` 提供进程总墙钟和峰值 RSS，已有阶段时间戳用于拆分。比较另开进程，不能从运行总时间里凭估计扣出来。

| 样本时点 | 要更新的预算 |
| --- | --- |
| 首个代表性真实专家调用 | 该尺寸 FC1/FC2 单调用墙钟、工作量与 RSS，不外推所有内核 |
| 完整 Qwen64/128 | 加载 110 模块及初始化开销、全前向各类内核占比 |
| 完整 Qwen64/4096 | 长流水下实际速度，修正不同规模的估计范围 |
| 后续形状明显不同的样本 | 若偏离已有估计，更新剩余用例，不无故重复测速 |

预算表写明“已用时间、有效样本、剩余同类工作量、初始化/比较成本、预计范围、必要重跑余量、未知项”。用同类内核的实际速度估计，不能把小 WGMMA 微测的速度乘所有数据量当保证。真实运行若成为交付瓶颈，再定位 CPU 功能计算/周期推进/日志的占比，处理主开销。
