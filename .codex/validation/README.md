# 分阶段验收与结果记录

更新：2026-11-07。当前阶段 0～7 均未运行验收。本文和各阶段表格是执行要求，不是通过报告。[阶段入口](../plans/README.md)；[性能口径与原基线](../hopper-validation.md)。

## 最少需要保存什么

每份记录应使另一位 agent 不靠聊天历史就能复跑：测试源码/输入位置、准确命令、外层和内层提交号、CUDA/ptxas 版本、实际加载的 libcudart 路径、PTX 周期模式、配置及散列、输出比较、周期和必要流量。复用阶段 0 的运行入口，不再为每阶段造一个框架。

结果放到实际运行目录，阶段文末只链接报告/日志并记录结论。拟采用 `workloads/moe/runs/hopper-stage-N/<test>/`；该路径目前未创建。完整九例继续使用原 `run.py` 和 `compare.py`，不修改冻结二进制、PTX、输入及容差以取得通过。

| 记录项 | 填写规则 |
| --- | --- |
| 实现状态 | 未实现 / 部分实现 / 已实现；列具体指令或接口及提交 |
| 验收状态 | 未运行 / 未通过 / 部分通过 / 通过；绑定实际提交和配置 |
| 数值证据 | 预期来源、比较结果；不能只填退出码 0 |
| 时序证据 | 周期、关键事件先后、流量或等待变化；只记录能回答本测试问题的量 |
| 剩余事项 | 触发条件、实际影响、是否阻塞当前消费者；未知写未知 |

功能预期尽量独立于实现：布局用手工坐标/值，矩阵用独立 CPU 运算，完整前向用现有 golden。不要把模拟器自己的地址或矩阵映射函数同时当预期生成器。检查合法程序；不为错误使用 PTX 建立恢复机制或大规模异常输入测试。

## 哪些检查必须精确，哪些只看主要误差

地址、离散索引、计数和 BF16 转换位模式精确比较。矩阵布局先用可精确表示、非对称的小值；普通浮点按对应比较规则。完整九例必须逐元素满足现有 `abs(actual-ref) <= 1e-5 + 0.02*abs(ref)` 且所有值有限。

约 20% 是设备执行时间的初期目标，不是数值容差。小程序验证完成顺序和延迟变化趋势；只有尺寸、launch 和缓存前序可比时，才计算相对硬件基线的误差。不能把所有小指令或微测都变成精确周期验收。

受影响的共用 SASS 路径做针对性回归：修改了什么就检查什么。没有可运行 trace 时说明未覆盖内容和原因；组件检查不能冒称 SASS 运行验收，更不能为补证据偷偷改成 trace 驱动的九例。

## 提前记录墙钟、初始化和 RSS

墙钟是本机运行模拟器花的时间，设备周期是预测 GPU 花的时间；两者分列。

1. 阶段 0 的首个测试开始保存 `/usr/bin/time -v`，得到进程总墙钟和峰值 RSS。在已有日志中标记装载/初始化结束、首个 kernel 开始与 kernel 结束；缺少分段时间时只补最小主机时间戳。
2. 阶段 1 首个真实普通内核，以及阶段 2 gating，分别记录初始化、模拟计算、输出比较时间。输出比较若在另一进程运行，单独计时。
3. 阶段 6 的 WGMMA 微测仅用于观察功能计算成本，不能直接外推九例。阶段 7 一有真实尺寸专家 GEMM 或完整 Qwen64/128，立即更新预算，再用 Qwen64/4096 修正。
4. 外推注明所用内核类型、尺寸、配置、有效样本和未知项。可用同类内核的 `模拟墙钟/设备周期` 估计同类剩余运行量；不同规模的 tile padding、缓存、轮询和 CPU 矩阵计算成本可能变化，不能对所有内核套同一比例。保留初始化、比较和重跑预算。

没有实测前不承诺九例几个小时跑完。计时本身不触发优化项目；只有实际运行妨碍当前验收时才定位瓶颈。可选关闭详细调试输出后用优化构建跑长用例，但记录构建方式，先确认所需功能测试仍通过。

## 何时停止

本阶段必要功能、同步、时序及受影响回归通过后推进。不要追加随机压力、未使用指令组合、任意 cluster 形状或全部非法输入测试。未通过时保存最小复现和根因；测试超时用于中止卡死并保留诊断，不在生产模拟路径新增超时后强制放行。
