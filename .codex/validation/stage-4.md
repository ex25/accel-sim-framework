# 阶段 4 验收：mbarrier

状态：未运行。[实现方案及六种指令](../plans/stage-4.md)；[公共规则](README.md)。

## 本阶段证明什么

到达和字节两个条件均满足才翻转本轮 phase，PTX 轮询得到正确 predicate。本阶段没有实际 TMA 时，非零字节测试只是组件验收，阶段5须重验真实数据返回。

## 测试与判据

| 测试 | 输入及执行方式 | 预期 |
| --- | --- | --- |
| 初始化/本地到达/轮询 | CUDA 最小程序 init→初始化发布 fence→本地 arrive→try_wait；安排有限延迟，让最后一个参与者晚到 | 最后到达前可观察到未完成，完成后返回真；不永久卡在发射前读取 trace 操作数 |
| 远端到达 | 两 CTA，mapa 定位同组另一 CTA 的屏障，执行远端 arrive，目标本地轮询 | 只改变目标屏障；相同 offset 的其它 cluster 不变；`_` 丢弃返回不丢副作用 |
| 两条件分别未齐 | 组件调用正式状态接口：到达齐/字节未齐，以及字节齐/到达未齐 | 都不翻转；最后一项满足才翻转一次 |
| 分批字节与先完成后expect | 使用未来 TMA 正式回调，先减字节形成负数，再登记expect并完成到达；另测分批配平 | 负数不报错或钳零，配平后完成；对应真实 TE 先发TMA再expect，不向生产路径加测试opcode |
| arrive.expect_tx 原子效果 | 在可能成为最后到达者时一次登记非零字节并到达 | 不在登记和到达之间错误完成；事务未齐仍等待 |
| 循环三轮 | 合法消费每轮结果后复用屏障，parity0/1/0，每轮使用不同标记 | 上一轮完成不能直接放行下一轮；不查询任意久远阶段 |
| 带/不带hint | 覆盖当前可选寄存器hint形式，让其它warp/CTA继续推进 | predicate正确；若实现挂起，完成或有界时间后可继续，纳秒按频率换算；若采用非挂起轮询，记录时间近似 |

组件测试在已经保证合法到达顺序的前提下使用完成回调；不制造无所属事务的重复通知再要求自动容错。每个操作/返回更新一次状态的检查通过事件计数完成，不引入生产环境去重恢复层。

## 保存哪些证据

记录 kernel/cluster/目标CTA/offset、phase、pending arrivals、tx 的变化及 predicate。日志应能解释“还有谁没到”或“还差多少字节”，不只输出 barrier id。程序输出与日志一起证明正确性。

初始化 fence 只验屏障初始化发布；不能将它作为任意 shared 数据发布或 TMA 等待的替代。PTX arrive 当前输出为 `_`，不扩未使用的 token 消费指令测试。

## 受影响回归与停止

若改动已有 mbarrier 状态类或 SASS 适配，检查原 SASS phase 编码在入口仍正确，以及同一个返回不会更新两次。与 PTX 轮询无关的其它内核专用逻辑不顺手重构。

零字节 CUDA 程序和非零字节组件通过后，推进 TMA；不能为了等待全搬运实现而停留本阶段，也不能把组件通过写成 TMA 已通过。
