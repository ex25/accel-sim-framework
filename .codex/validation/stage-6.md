# 阶段 6 验收：完整矩阵结果与异步行为

状态：未运行。[实现方案和指令清单](../plans/stage-6.md)；[公共规则](README.md)。

## 验收顺序

先查容量，再用普通shared准备输入验证单次WGMMA。矩阵存取可独立测试；单次WGMMA与非组播TMA通过就进行首次联测，不等本表所有项目完成。

| 测试 | 如何准备 | 通过条件 |
| --- | --- | --- |
| 64项链路组件 | 解析实际64寄存器tuple，检查decode输入/输出和依赖元数据，经过collector/写回测试 | 第8、32、63项及所有其它项均存在、顺序正确；输入累加器和descriptor不挤出容量。组件不冒充真实WGMMA |
| ldmatrix/stmatrix各自布局 | 四张8×8矩阵用不同整数位模式；独立检查每lane每packed word，再做往返 | 各自映射正确、每warp512B shared地址/请求合理；不能只以往返正确通过 |
| 单次WGMMA | 128线程普通shared写A/B，经CTA同步与proxy fence；寄存器初始化后wgmma fence，发起→commit→wait0→普通写出 | 全部8192项与独立预期一致，scale_d=0/1；A/B descriptor不是普通指针；一条逻辑运算仅算一次 |
| 四warp共同发起 | 四warp在相同合法操作前有不同长度的独立计算，再一致执行WGMMA | 收齐后形成一次操作，不漏warp、不重复计算，不能靠warp永远同时到达的假设通过 |
| 同累加器连续操作 | 多次WGMMA累加同一组寄存器，按合法fence/commit/wait规则执行 | 有序累加正确，后续异步操作可在前一项完成前发起；普通读受结果依赖限制 |
| 两组wait1/0 | 两套独立累加器分别提交组，延长第二组完成时间；wait1后只消费确定已等待的旧组，最后wait0 | wait1可在最新组尚未完成时返回，wait0等完；不能读尚未被等待的组来构造测试 |
| 寄存器配额 | 当前384线程、初始168/thread；先让消费者请求232，再让生产者dec40 | 两消费者不足时等待，生产者能继续并唤醒；总额64512不变，不跨CTA借用；PTX值不因虚拟编号大而截断 |

矩阵精确小值用于布局和依赖，再用一般有限值检查浮点误差。CPU参考与模拟器布局/运算函数独立；真实输出不能因CPU和GPU累加顺序不同就自动放宽既定容差。

## 提前交叉测试

单次运算通过后，执行[阶段5首次联测](stage-5.md#early-integration)，普通store输出所有结果。报告仅保存一份并在此引用。该测试不等待setmaxnreg、组播和TMA输出；通过不代表连续异步组已验收。

## 完整双缓冲和时间模型

阶段5输入/输出与本阶段组/配额齐备后，用两块不同tile组成合法流水，交错普通cp.async、TMA bulk和WGMMA组，确保每个wait只作用于自身类别。对照合法串行版本：结果相同，流水中可见搬运/计算重叠。分别增加搬运或矩阵延迟，相应等待应增长，不能把其它独立工作全停住。

检查 shared 输入在 WGMMA 不再需要后才复用，以及输出源 read wait 与最终 global ack 的区别。不要以提前读取或覆盖在途数据得到的快周期作为重叠证据。

一个逻辑 m64n128k16 对应262144次math op；核对四warp发射与单份功能计算/资源计量关系。GMMA资源必须出现在PTX实际配置和路由中；64/64是现有trace按N=128求得的初值，不是PTX的已校准结果。collector/writeback覆盖全结果，已有bank/端口继续计时；不要求新增精细物理bank重分配。

记录单次/流水的墙钟与RSS，观察CPU功能计算成本；这只是微测，不能直接宣称九例速度。真实尺寸专家调用一旦可用，按阶段7马上更新预算。

## 受影响回归与停止

容量和scoreboard改动回归普通少量输出指令、load/store依赖及已有矩阵路径；GMMA专用资源/等待改动回归受影响SASS。不能把为WGMMA设置的依赖例外扩成所有指令都跳过冲突。

全结果、异步组、配额、联测和受影响回归通过即推进，不增加其它矩阵形状、非法warpgroup执行或未使用配额组合。
