## 1. 完整 64 项和分批写回

### 解析/解码组件检查

使用模块 16 的真实 WGMMA tuple，另以 64 个不连续编号的寄存器构造一个等价语法样例。逐项比较解析、decode、依赖目标、collector 元数据与源 tuple 的顺序；不是只检查列表长度。特别打印 j=7、8、31、32、63 的对应项，完整比较仍涵盖其余位置。

scale_d 为真时确认全部 64 个累加器和实际描述符/谓词输入都能表示；为假时不应功能性读取未初始化 D。普通双输入单输出指令的实际访问数量保持原值。

这是组件检查，不声称矩阵执行已经通过。单次真实 WGMMA 输出是下一步不可省的证据。

### 写回端口组件与实际指令检查

在现有 collector/写回测试入口放入 64 个有效目标，使其中多个目标落到同一个 bank；给它们不同值。按周期记录本周期服务项、剩余项、完成标记和依赖状态：

1. 第一次服务不够时保留指令，只清除已服务项；下一周期从剩余项继续。
2. 最后一个目标服务前，GMMA outstanding、指令完成计数和待写依赖不能先清空。
3. 最后服务后只完成一次，写次数不能因重试被多计。逻辑目标列表仍完整，不能被端口进度清空。
4. 普通后继消费 j=63 的指令得到正确值。真实 WGMMA 也经过同一写回路径，不能仅让专用组件绕开上层而通过。

若配置 bank 数/端口变化，用同一合法输入确认写回服务周期按资源变化；不规定脱离配置的固定总周期。

## 2. ldmatrix 与 stmatrix 分开验证

四张矩阵 `q=0..3`，每张 8×8。元素使用原始 b16 值 `V(q,r,c)=1000*q+10*r+c+1`，四张矩阵分开存放并按行提供 16B 对齐地址。

- **只测加载：**由普通 shared store 写入 V，执行 ldmatrix.x4，再用普通 global store 导出每个 lane 的四个 b32。lane `4r+c` 的第 q 项低 16 位应是 `V(q,r,2c)`，高 16 位是 `V(q,r,2c+1)`。例如 lane0/q0 是低 1、高 2；lane31/q3 是低 3077、高 3078。
- **只测存储：**直接在寄存器构造上述 packed 值，执行 stmatrix.x4，CTA 同步后用普通 load/store 导出 shared，逐元素与 V 比较。不得用刚被测的 ldmatrix 生成输入或检查输出。
- 核对请求地址集合覆盖四张矩阵的 512B；请求可以按现有规则合并，不要求“一条 PTX=一个内存请求”。额外往返不是通过的必要条件。

## 3. 单次矩阵和描述符布局

使用一个 128 线程 warpgroup。普通 shared store 准备 A/B，CTA 同步并执行 shared proxy fence；如使用初始 D，则初始化寄存器后执行 wgmma.fence。随后一条 mma、commit、wait0，普通 store 导出所有线程的 64 项。

定义可精确表示的非对称小整数：

```text
A[m,k] = (m%7)-3 + (k%3)
B[k,n] = (n%11)-5 - (k%2)
D0[m,n] = (m%5) - (n%3)
```

CPU 独立计算 `C[m,n]=Σ(k=0..15) A[m,k]*B[k,n]`。scale_d=0 应得到 C；scale_d=1 应得到 C+D0。输入整数可被 BF16 精确表示，当前小和可被 FP32 精确表示，这一组精确比较，不借用真实大矩阵的容差掩盖布局错误。

保存原始 `[thread][tuple位置]` 输出，再按公开分布独立检查。人工锚点为 t0/j0→(0,0)、t0/j2→(8,0)、t0/j4→(0,8)、t127/j63→(63,127)；完整比较覆盖所有 8192 项。实现和预期不得共同引用同一映射函数。

### 描述符覆盖当前实际布局

分别检查真实 64B、128B swizzle 形式，包含冻结 PTX 使用的非零起点/base offset。先用独立的 16B 块地址表放置 A/B，再发 WGMMA；不能用模拟器 descriptor 解码器准备输入。表中注明起点、LBO、SBO、相位与至少两个八行组的实际地址，防止只验第一小块。

K-major swizzle 的 LBO 按规范不参与寻址；SBO、非零起点和相位必须有跨块样例。无 swizzle 若作为实现过程的辅助微测，单列其状态；最终不能只靠无 swizzle 通过代替真实布局。

四 warp 在共同 WGMMA 前各做不同长度的合法独立计算；记录共同操作在四 warp 到齐后形成，逻辑计算数为 1，不能执行四份整矩阵。再用同一 PC 的两轮循环确认动态身份不会混用。

## 4. 连续累加、fence 和 wait1/0

### 同一套累加器的连续 WGMMA

使用上述 A/B。在一次提交前连续发两条相同形状 WGMMA，第一条 scale_d=0、第二条 scale_d=1，commit 后 wait0，预期为 2C。选择足以容纳两条操作的配置，记录第二条发起在第一条全部写回结束之前，且两条仍按累加顺序取值。

这证明没有隐式逐条 wait0；只记录 CPU 功能函数调用时间先后不算证据。另用普通指令初始化 D0、wgmma.fence、scale_d=1，证明普通寄存器值能按顺序进入矩阵计算。不要通过删除必要 fence 制造未定义行为测试。

### 两个已提交组

用两套独立累加器 X/Y：第一组计算 C 到 X 并 commit；第二组计算 2C 到 Y 并 commit。执行 wait1 后只消费 X，最后 wait0 后消费 Y。

用组件级可控完成事件使第二组晚于第一组：旧组写回完成后，wait1 可返回，Y 仍未完成；wait0 必须继续等待。实际 PTX 测试记录自然发起/完成与输出；若两组都提前完成，数值通过但不能据此宣称已验证 wait1 的提前返回分支，补用上述组件事件证据。

在两组间保留一个尚未完成的普通 cp.async 组或 TMA bulk 组的受控测试，确认 WGMMA wait 不替它们排空。各组消费均遵守自己的 wait，禁止用读未完成结果的非法程序检查队列隔离。

## 5. 额度不足等待和生产者归还

用 384 线程、三个 warpgroup，测试配置/资源元数据设为当前实际初始 168/thread。明确测试中的物理资源来源；不能因为 PTX 声明了很多 `%f` 就声称初始配额已是 168。

先让两个消费者到齐并请求 inc232，再让生产者执行 dec40。组件记录在生产者归还之前两申请均因空闲 0 等待，但生产者仍能调度；归还 16384 后各授予 8192，最后三组额度分别为 5120/29696/29696，总额恒为 64512。PTX 测试确认全部线程能完成并输出各组标记。

在 dec 前后保留合法存活的高编号 PTX 虚拟寄存器值，确认未被额度机制截断。CTA 退出时 SM 归还原 64512 一次；一个相邻 CTA 的池不能因本 CTA dec 得到额度。该项复用阶段 3 的资源计数检查，不另做大量并发压力测试。

## 6. 首次联测、完整流水和时间

单次矩阵与非组播 TMA 可用，就执行[阶段 5 首次联测](stage-5.md#early-integration)。报告保存一份，在两阶段引用；不等 setmaxnreg、stmatrix 和 TMA 输出齐备。

完整能力具备后，用两套 shared 缓冲、两组不同输入组成合法流水：TMA 输入和 mbarrier 完成后计算；等 WGMMA 不再使用旧输入后才复用输入缓冲；结果经转换/stmatrix 后用 TMA 输出，read wait 后才覆盖输出源。对照同样工作的合法串行版本，检查结果相同，流水确实出现搬运与计算重叠。

分别增加 TMA 搬运服务延迟、GMMA 延迟或发起间隔，受影响的等待/总时间应增长，其它可独立工作的 warp 仍能推进。只改变一个参数来解释变化，不要求所有微测达到硬件 20% 误差。

核对以下计量：一次逻辑 WGMMA 为 262144 math op，四 warp 的发射数单列；全部寄存器写回真实服务；GMMA 使用 PTX 实际配置中的资源，64/64 只标为由当前 SASS 形状计算得到的初值。不能把 CPU 单次矩阵计算墙钟当 GPU 延迟。
