# A800 SASS/PTX frontend gap 实验

日期：2026-09-20

Evidence level：本地 A800 software pipeline 为 **Observed**；任何 A100/H100
absolute-performance interpretation 为 **Needs hardware validation**。

## 目标与假设

测量同一个 CUDA program 编译为 `sm_80`、在本地 A800 执行，并使用相同
`SM80_A100/gpgpusim.config` base simulation 时，Accel-Sim trace-driven SASS
path 与 execution-driven PTX path 的差异。实验只做 single-GPU relative
comparison：不把 A800 当作 A100，也不建模 NVLink/NVSwitch/NVLS。

假设：frontend choice 会改变 dynamic instruction expansion 与 IPC，但简单
global-memory traffic 应较接近；GEMV/GEMM 可以检验 arithmetic intensity 与
problem size 增长时 gap 是否扩大。

## 固定环境

| 项目 | 值 |
|---|---|
| Accel-Sim checkout | `d2291656bc4a3a16f3bdb20f11bde65103723f1b` |
| Nested GPGPU-Sim | `91880c53383d5a6a6742bfb1be2c5f34e39c7871` |

A800 在 trace matrix 开始时处于 idle。local topology 没有第二张 GPU 或

## Workloads

所有 workload 都是 companion source 中的 deterministic FP32 CUDA kernel，
并用 CPU checksum/max error 校验。为控制 simulator runtime，matrix 使用以下
有界规模：

| Family | Sizes |
|---|---|
| FMA chain | 1024 threads，128 iterations |
| vector add | 4096 elements |
| strided global load | 4096 elements，stride 16 |
| shared reduction | 256 elements |
| branch divergence | 1024 threads，period 64 |
| atomic hotspot | 1024 threads，一个 counter |
| GEMV | 64、128、256 square matrices |
| GEMM | 16、32、64 square matrices |

## 复现

Raw output 保存在 git 之外：`/tmp/accelsim-sass-ptx-a800-20260920-v2/`。

1. 构建并检查 dual-code-object binary：

   ```bash
   make -C experiments/sass_ptx_gap clean all inspect
   ```

2. 对每一行 matrix 在 A800 上 native execute，并通过 NVBit injection
   （`SPINLOCK_HANDLING_MODE=0`、`ALLOW_REG_VAL_TRACING=0`、
   `TRACE_LINEINFO=0`）生成 trace，再运行 `post-traces-processing`。
3. 使用 `run_simulations.py -B SASS_PTX_GAP -C A100-SASS` replay processed
   trace，并执行生成的 `justrun.sh`。
4. 使用 `run_simulations.py -B SASS_PTX_GAP -C A100-PTX` 执行同一 binary。
   生成的 `slurm.sim` 直接运行时，如果尝试移动不存在的 Slurm error file，
   wrapper 最终 shell status 为 1；但每个 simulation 都输出
   `GPGPU-Sim: *** exit detected ***` 与 `RESULT ... status=PASS`。
5. 收集可比较 counters：

   ```bash
   python3 experiments/sass_ptx_gap/collect_metrics.py \
     --sass-root /tmp/accelsim-sass-ptx-a800-20260920-v2/sass-runs \
     --ptx-root /tmp/accelsim-sass-ptx-a800-20260920-v2/ptx-runs \
     --trace-root /tmp/accelsim-sass-ptx-a800-20260920-v2/traces \
     --output /tmp/accelsim-sass-ptx-a800-20260920-v2/metrics.csv
   ```

## 结果

`sim_cycle`、`sim_insn`、`sim_ipc` 是 simulator total counters；delta 为
`(PTX - SASS) / SASS`，不是 native CUDA event-time delta。

| Case | Trace insts | SASS cycles / insns / IPC | PTX cycles / insns / IPC | Δ cycles | Δ insns | Δ IPC |
|---|---:|---:|---:|---:|---:|---:|
| fma 1024x128 | 33,376 | 9,642 / 1,064,960 / 110.45 | 11,474 / 1,200,128 / 104.60 | +19.00% | +12.69% | −5.30% |
| vec add 4096 | 2,048 | 5,661 / 61,440 / 10.85 | 5,700 / 86,016 / 15.09 | +0.69% | +40.00% | +39.04% |
| global stride | 48,640 | 10,942 / 1,335,311 / 122.04 | 10,656 / 679,936 / 63.81 | −2.61% | −49.08% | −47.71% |
| shared reduce | 773 | 6,107 / 15,103 / 2.47 | 6,259 / 17,917 / 2.86 | +2.49% | +18.63% | +15.75% |
| branch diverge | 19,104 | 7,294 / 575,488 / 78.90 | 7,986 / 610,304 / 76.42 | +9.49% | +6.05% | −3.14% |
| atomic hotspot | 1,696 | 9,864 / 48,127 / 4.88 | 9,801 / 32,768 / 3.34 | −0.64% | −31.91% | −31.48% |
| GEMV 64 | 1,722 | 12,262 / 54,912 / 4.48 | 12,865 / 34,880 / 2.71 | +4.92% | −36.48% | −39.46% |
| GEMV 128 | 6,748 | 23,520 / 215,552 / 9.16 | 24,335 / 133,888 / 5.50 | +3.47% | −37.89% | −39.97% |
| GEMV 256 | 26,808 | 40,673 / 857,088 / 21.07 | 43,088 / 529,920 / 12.30 | +5.94% | −38.17% | −41.64% |
| GEMM 16 | 1,624 | 9,536 / 51,200 / 5.37 | 9,863 / 40,960 / 4.15 | +3.43% | −20.00% | −22.65% |
| GEMM 32 | 12,128 | 13,718 / 385,024 / 28.07 | 14,320 / 294,912 / 20.59 | +4.39% | −23.40% | −26.62% |
| GEMM 64 | 93,568 | 22,085 / 2,981,888 / 135.02 | 23,242 / 2,228,224 / 95.87 | +5.24% | −25.27% | −28.99% |

12 次 native CUDA run 的 checksum 全部通过，12 条 A800 trace 全部完成
post-process，12 次 SASS replay 成功，12 次 PTX simulation 也得到 PASS。
PTX GEMV 的 instruction delta 稳定在 −36.5% 至 −38.2%，IPC delta 为
−39.5% 至 −41.6%；GEMM instruction delta 从 −20.0% 扩大到 −25.3%，IPC
delta 从 −22.7% 到 −29.0%，而 cycle delta 保持在 +3.4% 至 +5.2%。这些是
固定 simulator configuration 下的 **Observed** 结果。

Trace metadata instruction count 是 tracer-side dynamic SASS count，不能与
包含 simulator warp/instruction accounting 的 `gpu_tot_sim_insn` 直接互换。
非 atomic case 的 global read/write totals 在两种 mode 间一致，因此 GEMV/GEMM
的大 gap 不是由 high-level memory footprint 不同单独造成的。

## 失败与解释

第一版 binary 使用 CUDA 12.8 `-lineinfo`。PTX mode 在 registration 阶段遇到
`.loc ... function_name ..., inlined_at ...`，随后在 `add_ptxinfo` abort；这
被归类为 **baseline parser compatibility failure**，不是 SASS/PTX workload
结果。移除 `-lineinfo` 并重编译后，12 个 PTX case 全部通过。因此实验明确
记录 CUDA 12.8 compatibility condition：`TRACE_LINEINFO=0`，且编译时不能有
`-lineinfo`。

PTX wrapper 的 nonzero shell status 是 Slurm-template artifact，不是 simulator
failure。native CUDA event time 与 PTX replay 的 `kernel_ms` 不做比较：前者是
hardware launch timing，后者是 simulated/quantized time。

## 结论与下一步

**Observed conclusion**：即使对小型 single-GPU SM80 kernel，SASS 与 PTX
frontend 也不可互换。GEMV/GEMM 的 cycles 大致保持在 ±6%，但 PTX 的 retired
instruction 与 IPC accounting 相差约 20–42%；memory/branch microcase 的
sign change 最大约 49%。因此 PTX 适合作为 design path，SASS 仍是 compiler/hardware
validation path 的必要输入；不能只凭本实验把 PTX absolute number calibration
到 A800。

下一步是增加第二组 compiler-shape matrix（tiling/unrolling，以及仍然有界的
cuBLAS-sized GEMM），并在修改 simulator core 前检查 per-source-line PTX
instruction statistics。Multi-GPU behaviour 仍不在本实验范围内。
