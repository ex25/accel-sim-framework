# Hopper PTX 规划：已确认的取舍

2026-11-05 至 2026-11-06，经用户在 `grill-me` / `grilling` 讨论中确认。这里集中保存路线决定；具体执行顺序见[实施计划](hopper-plan.md)，事实依据见[调查笔记](hopper-notes.md)。

| 决策 | 已确认内容 |
| --- | --- |
| 当前优先级 | 尽快让已冻结的九个 MoE workload 在 PTX 周期级模式下运行，并用于性能估算。后续需要时再提高精度。 |
| 性能观察层级 | 同时关注可比的整体设备耗时和主要耗时内核；接受小差距，避免大偏差被总耗时掩盖。 |
| 时序实现时机 | 主要时序机制随功能一起实现，各阶段验证；代表性内核具备后及时校准，不积累到最后。 |
| 初期精度 | 暂以约 20% 的耗时相对误差为目标，不追求论文宣称的 10%。数值结果按已有比较规则检查。 |
| 问题处置 | 优先修正运行阻塞、错误计算/同步及明显时序失真；小偏差和低影响问题先记录，不为 corner case 添加大量防御代码。 |
| 实现策略 | 按共用组件和真实依赖分组，前置问题先于消费者处理；优先复用 Accel-Sim/GPGPU-Sim 已有实现。 |
| 交付位置 | 规划、验证方案和问题记录放在项目根目录 `.codex/`。 |
| 访谈范围 | 已确认的取舍不重复询问；后续使用 `grill-me` 讨论真正影响实施路线的新决策。 |
| 九例初期性能参照 | 接受现有 ncu 逐内核时间之和，三个 4096-token 用例用自然运行时间线交叉检查；不把包含主机提交间隙的裸跑 CUDA event 当纯设备时间。九例自然运行完整设备时间留待以后补验。 |
| tensor map 编码 | 使用模拟器自己的 128 字节内部描述符，保存真实地址、形状、步长等参数，供主机编码和 PTX 复制、修改、TMA 搬运共同使用；不要求与真实 GPU 的不透明编码互换。 |
| 寄存器配额与占用 | 保留 `setmaxnreg` 的 warpgroup 同步、额度增减及不足时等待；按已核实的 CTA 物理资源计算占用。影响不大的额外物理 bank 重分配细节先暂缓，已有 bank/端口时序通路照用。 |
| WGMMA 结果与异步 | 每线程 64 项结果必须沿解析、执行、依赖与写回完整传递；WGMMA 必须保留异步组语义，不得每次矩阵计算都强制等待。两项均在本任务阶段 6 完成，作为 WGMMA 的验收要求。 |
| 内存边界 | 本机有 256GB 内存，优先保留必要的完整状态，不为省内存截断结果；记录实际占用，避免无用副本。 |

## 2026-11-07 补充确认

| 决策 | 已确认内容 |
| --- | --- |
| 提前联测 | 非组播TMA输入、mbarrier和单次WGMMA分别通过后，立即串联到普通store；不等组播、TMA输出和配额全部完成，完整流水仍需后续验收。 |
| 提前记录模拟成本 | 首个真实普通内核开始记录初始化/模拟墙钟和RSS；代表性真实专家一旦可用就更新九例预算，不等最终集成结束。 |
| 详细交付文档 | 原plan/validation作为概览，plans/和validation/按阶段保存实现及验收；明确所需指令、实现方法、SASS复用、事实影响和未完成状态。 |
| 当前范围优先 | 对当前九例影响低且实现繁琐的细节可记录暂缓；不加无依据防御代码/验证，不放宽数值、必要同步和主要时序要求。 |
