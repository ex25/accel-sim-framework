# Hopper 分阶段硬件对照：通用执行 prompt

你负责为用户指定的 Hopper PTX 实现阶段建立真实 GPU 对照。项目当前路径为 `/home/wangjz/in-switch/accel-sim`，核心模拟器在独立 Git 仓库 `gpu-simulator/gpgpu-sim/`。用户另行指定阶段 N、已有实现/验收记录及本轮样本范围；阶段明确时直接执行，仅在上下文无法确定时问清，不默认扩展到其它阶段。本文不固定某一阶段或模块清单，每次复用时正文无需修改。

目标是在每个阶段交付时，用**相同 PTX、相同输入、相同启动参数**分别在真实 GPU 和模拟器上运行，检查输出、工作量、访存量和耗时，尽早发现大偏差。真实 H100 通过 **Modal** 租用，GPU 任务在 Modal 容器中执行，本地只做准备、结果整理和模拟器运行；优先减少 GPU 占用、远端存储和网络传输。

本轮实际实现并运行必要工具，不只写方案。不修改模拟器、生产配置、冻结 PTX 或数值容差来取得通过；发现实现错误时保存复现交执行 agent 修复。保留已有改动和证据，未获指示不提交、不向其它聊天发消息。

只覆盖指定阶段的最小必要样本：优先已有、已验收的测试输入和本阶段真实消费者，不另做全 workload 中间状态捕获，不建设通用 CUDA checkpoint/重放平台。本阶段没有可独立运行的真实消费者时，使用其合法微测或组合测试，不要求提前实现后续阶段。

当前项目已有九例完整前向的硬件计数，可作背景参考。**本任务不补全九例自然时间线、不测全部 110 模块/206 次调用**，也不把原完整前向数据充当本次人工输入的硬件结果。

## 2. 在本地准备，通过 Modal 运行

先完成无需 GPU 的源码整理、输入/参考生成、参数提取及包完整性检查，再到租用机器编译和采集。复用已有 runner，增加必要的 native/sim 选择及按样本启动能力；不为每个阶段复制一套框架。

每个样本保存小型 manifest：样本 ID、阶段、PTX/源码散列、entry、数据类型与尺寸、输入生成规则/seed、输入校验散列、参数布局、grid/block/动态 shared，以及实际需要的其它启动属性。同 entry 的不同用途或尺寸分别编号。

**优先保存生成输入的方法，不保存大块 GPU 内存快照。**在租用 GPU 和本地分别执行同版本的确定性生成器，用有效数据的散列确认输入一致。初始化配方、固定整数位表、CPU 数学参考都可复用。地址本身可不同，指针与缓冲区的对应关系必须一致；不要将运行时指针值计入可移植输入散列。

样本不得依赖前序 GPU kernel 提供输入。现有串联测试如需前序结果，优先使用已有 CPU 参考生成这个合法中间输入，明确其布局、顺序和初始化值，再交两端运行。不能因为前序输出数值相同但排列不同，就声称后续 kernel 的输入逐字节一致。不要先开发从完整前向导出全部中间张量的工具。

每轮启动前恢复相同的输入、原地输出和工作区，准备/恢复不计入目标 kernel 时间。后续阶段涉及 tensor map 等对象时，在该阶段按相同逻辑参数分别编码；不传递绑定旧地址的 opaque 字节，也不在本轮提前实现。

远端只需要本阶段的源码、选中的 PTX、小型参数/生成配方和依赖说明。不要要求上传整仓库运行目录、完整权重、所有 case 的 forward.bin/golden 或模拟器构建；可本地提取的小型 launch 元数据直接打包。给出最小依赖和实际包大小。

## 3. 先算对，再测必要数据

在 H100 确认型号、SM 数、驱动/CUDA/采集工具及实际加载的 native libcudart；模拟器侧确认加载其 libcudart、`PTX_SIM_MODE_FUNC=0` 和实际配置。记录频率/限频、MIG 或共享使用等实际影响条件，不擅自更改全局 GPU 设置。

先跑一个小代表确认环境和数值，再完成指定阶段的全部选定样本。保留原 PTX、合法尺寸和启动参数。输出必须全量比较：离散索引/计数及规定的 BF16 位模式精确；浮点沿该测试原有规则，普通消费者要求有限且逐元素满足 `abs(actual-ref) <= 1e-5 + 0.02*abs(ref)`。专门测试 NaN 的微测沿其类别规则。不能只存退出码或一个输出 hash 代替实际比较；可以在远端完成比较后只回传结果与散列。

每个目标 kernel 单独记录以下紧凑指标，名称以安装工具的查询结果为准：

| 必要数据 | 用途 |
| --- | --- |
| GPU kernel duration | 与模拟器目标 kernel 区间比较，不含输入生成、H2D、恢复、下载和主机间隙 |
| SM elapsed cycles avg/max、有效频率 | 解释硬件周期和运行频率，不能当全 GPU 周期直接相加 |
| DRAM 读/写字节 | 检查主要外存流量是否一致 |
| L2 读/写 sector 与命中率 | 区分访问量和缓存影响；sector 按对应指标定义换算 |
| 动态 SASS warp 指令数 | 辅助检查工作量/控制流，不直接等同 PTX 指令数 |

Tensor 运算量只在本阶段含 Tensor 计算时增加。实际 occupancy、L1/TEX、shared bank conflict、issue 活跃度和停顿采样只在明显差额需要归因时定向补，不默认全指标采集或 `--set full`。

计时与 ncu 计数分开，优先复用已有轻量设备时间戳入口，必要时只捕获目标 kernel 的 GPU activity。小 kernel 不用含主机提交间隙的时间替代其执行时间。每个目标至少保存三次恢复同一输入的计时样本，报告 median 和 min/max；计数先取一份有效样本，有异常再重复。ncu 的多个 replay pass 不算多个独立样本。

记录输入恢复、预热、cache/clock 设置、实际频率和 replay pass 数。输入字节相同不代表缓存与完整前向相同；本任务测的是明确定义初始化条件的独立 kernel。不要把 ncu 采集期间应用自身被放大的 CUDA event 当自然 kernel 时间。指标不可用时写原因，不填零伪装测得。

## 4. 与模拟器直接比较

租用机器完成 native 数值/计时/计数即可，不需要在那里编译运行模拟器；回到本地使用相同输入生成器、PTX 和参数运行 sim。硬件采集权限或环境缺失时明确报告，不用估算值填成实测。

性能必须使用可比的设备配置。一个 SM 的调试配置不能直接与完整 H100 计算误差，更不能乘除 SM 数换算；优先用完整 H100 配置跑本阶段样本。若完整配置有实际阻塞，保留单 SM 正确性证据，性能项标为未完成，并报告复现，不越权修模拟器。

模拟端记录 kernel 真正开始至完成的设备周期差，排除纯 launch 等待，按实际 core MHz 换算时间。逐 kernel 列出：数值结果、硬件时间及波动、模拟时间、有符号偏差、DRAM/L2/相关工作量。已有证据无法保证计时范围或缓存条件可比时明确说明，不给出误导的精度结论。

对稳定的大偏差，先查输入/初始化、实际工作量、地址/流量、等待和频率，再判断是实现错误还是时间模型近似。小偏差记录后继续；约 20% 是整体/主要 kernel 的初期目标，不要求每个微测或小 kernel 达到它。小 kernel 同时报绝对时间差，避免只看百分比。不要为压进阈值反复调参。

## 5. 小型交付与停止

统一代码优先沿用已有测试目录；检查 `.gitignore`，避免新增源码被忽略后遗漏交付。按阶段保存结果到 `.codex/execute/hardware-baseline/stage-N/README.md`，原始运行数据留对应 run/evidence 目录，不复制进阶段实现/验收记录。

回传内容以**源码/生成器、manifest、JSON/CSV 汇总、必要精简日志**为主：

- 输入生成及运行命令、两端代码/PTX/库/配置散列、GPU/工具版本和测量条件。
- 每个样本全量比较结果、元素数、最大误差/失败数量、输入和输出散列；异常时只增加必要差异位置及可复现信息。
- 每次计时原样本、计数值/单位、采集命令、缺失指标原因及逐 kernel 对照表。
- 列样本、跑单个样本、跑本阶段集合及比较已有结果的直接命令。

完整输出由远端比较后可重新生成，不要求下载；原始 ncu/nsys 报告仅保留本阶段实际使用的少量记录，需要归因时再回传对应报告。不长期保存或传输 GPU 内存快照、巨量 stdout、可重建二进制及无关产物。打包前列出文件清单与总大小，默认以 **20MiB 以内的小型交接包**为目标，超出先清理重复/可再生内容并说明实际体积，不删除必要失败证据来凑大小。

记录准备、GPU 采集和本地 sim 的墙钟及实际存储/传输字节，便于后续阶段估计租用成本，不承诺未经实测的总预算。必要样本的数值、硬件测量、可比 sim 对照及小型可复现交付完成后停止，不自动追加其它阶段或全 workload 采集。遇到实现阻塞则交付复现、已完成范围和未完成项。
