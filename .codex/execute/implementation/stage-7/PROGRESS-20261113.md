## 5. 计时口径：后续如何与硬件比较

| 数据 | 范围与用途 |
| --- | --- |
| 模拟首CTA→完成 | kernel执行及必要等待；用来审查执行模型，对照nsys GPU kernel start/end，仍保留硬件/模拟起点不完全相同的边界。 |
| 模拟含启动区间 | 原始gpu_sim_cycle另列；当前配置比首CTA执行段多5002周期，其中启动等待5000。1980MHz下5000周期约2.525µs，**不是2.5ns**。不能假定ncu恰好多算这一固定费用。 |
| 完整前向E2E | 必须用同一前向起止位置的CUDA events；包括前向内部操作，排除初始加载/输入上传及最终输出下载。不以kernel之和代替。 |
| 无profiler硬件event | 后续E2E主基线。nsys组同时保留event用于观察工具扰动，不能替换无工具基线。 |
| nsys | 保存每次GPU kernel start/end、拷贝/同步/API时间线；作为逐核基线。它仍有观测开销。 |
| 旧ncu | 用于历史计数器和原因分析；预热、重放等条件与新数据不同，不能把ncu/nsys差异全部归为工具开销。仅在某核大残差需定位时再单测。 |

**formal-v2完整event尚缺。**128/4096的0.565281/1.266643 ms是ROI检查点差，不能改称直接event E2E。旧库有独立event，但库和运行条件不同；不与新硬件预热数据拼成统一验收表。

未来完整模拟入口已默认启用event；当前模拟库的cudaEventElapsedTime返回主机墙钟，必须用现有GDB observer读取stream event设备周期戳。相同冻结库的两kernel短测已验证：11224周期=0.005668687 ms，而legacy运行时返回3000 ms。它只验证采集路径，不替代完整MoE。
