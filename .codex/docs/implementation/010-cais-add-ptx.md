# 010 — Minimal single-GPU custom PTX instruction

## Problem

The PTX-primary strategy had an SM90 execution baseline but no demonstrated
custom opcode. Before adding CAIS/in-switch communication semantics, the
project needed a local instruction with explicit operands, result, dependency,
timing, and completion behavior.

## Design

`cais.add.u32 dst, src1, src2` is an intentionally narrow prototype. It is
unsigned modulo-32 addition, writes one register, has no memory or network side
effect, and aliases the configured integer `ADD` latency, initiation interval,
and `INTP_OP` resource. A deterministic CUDA kernel creates a dependent chain
of one or 32 additions per thread. Its PTX is generated by `nvcc`, then one
opcode is rewritten for the custom fixture; all other instructions remain the
same.

## Implementation and call path

The nested GPGPU-Sim commit `8f3c35fa` changes only five files: lexer token,
opcode table, functional implementation, timing mapping, and the CUDA-6+
external-PTX loader. The loader change is required because the existing
`PTX_SIM_USE_PTX_FILE` behavior only covered the pre-CUDA-6 path; without it,
the first control/custom comparison silently parsed the embedded ordinary
`add.u32`. The proposed external fixture bypasses stock `ptxas` PTXInfo loading,
because `ptxas` cannot assemble an unknown opcode.

The effective path is:

```text
external PTX fixture → CUDA-6+ loader override → ptx.l lexer/parser
  → CAIS_ADD_OP PTX IR → cais_add_impl register update
  → integer ADD timing/resource class → shader issue/dependency/completion
```

The main-repository workload, fixture generator, launcher, and checker are
recorded in `.codex/experiments/2026-09-21-cais-add-ptx.md`.

## Validation

The 4096-element control/custom pairs passed for one and 32 dependent
iterations. Both pairs had identical cycles, instruction counts, IPC,
checksum, and zero maximum error; the 32-iteration case had more work than the
one-iteration case. The existing SM90 baseline still passed at 5501 cycles,
1654784 instructions, IPC 300.8151, and max error `3.576278686523437e-07`.

This is **Verified** simulator-software evidence. It is **Needs hardware
validation** for any claim about a real ISA, latency, throughput, occupancy, or
SASS encoding. The instruction has no communication semantics by design.

## Build notes and limits

Use `cmake --build ...` followed by `cmake --install ...`; the latter updates
the activated simulator library. The release build completes with existing CUDA
internal-header/pointer-cast warnings and tolerates the missing optional
`/home/wangjz/.local/bin/stubgen`. CTest currently has no registered tests.

Skipping PTXInfo for a proposed external opcode is a harness boundary, not a
production solution. A future implementation must provide assembler and
occupancy metadata, then separately define how an instruction emits a
communication event. No multi-GPU or network behavior was changed here.
