# Experiment plan

Experiments are split into a PTX design path and a SASS/hardware validation
path. Every result must say which path produced it.

## PTX design path

1. Run a small SM90 PTX benchmark with no custom instruction.
2. Add one custom communication instruction with no network side effect, and
   check parser, functional result, issue timing, dependency and completion.
3. Add a synthetic communication event generated by that instruction.
4. Run two logical PTX GPU contexts through the event orchestrator and BookSim.
5. Sweep 2/4/8 logical GPUs, Ring, then NVLS-style multicast/reduction, with
   message sizes from 1 KiB to 256 MiB.

Metrics include instruction/cycle counts, event ready/completion time, bytes,
flits, effective bandwidth, link/switch utilization, reduction occupancy,
stall time, and compute/communication overlap.

## SASS validation path

Use A800 traces to validate the software pipeline and use H100/H200 traces when
checking existing Hopper instruction behaviour. Do not use an A800 trace to
claim H100 ISA or NVLS performance. When both paths run the same high-level
kernel, compare them as a validation experiment, not as interchangeable inputs.

## Reproducibility metadata

Every run records Accel-Sim SHA, nested GPGPU-Sim SHA, BookSim SHA/config,
input path (PTX/SASS/synthetic), workload, rank count, collective/algorithm,
message size, seed, command, output path, date, and evidence level under
`.codex/experiments/`. Large traces and raw results remain outside `.codex/`.
