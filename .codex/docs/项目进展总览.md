# Accel-Sim + BookSim + NVLS 项目进展总览

更新时间：2026-09-20

本文是从项目开始到当前状态的中文历史记录。它面向六个月后重新进入
repository 的研究者，重点说明已经实际做过什么、哪些结论有源码或实验
证据、哪些仍然只是设计假设，以及下一步为什么这样安排。

## 1. 项目目标与边界

长期目标是以 Accel-Sim 为 GPU compute timing 基础，引入 BookSim 风格的
GPU interconnect timing，并逐步建立单节点 H100/H200 + NVLink + NVSwitch +
NVLS 的研究模型。第一阶段目标是 2/4/8 个 logical GPU 的 AllReduce，比较
Ring 和 NVLS；跨节点 InfiniBand、完整 NCCL 和集群级 MNNVL 不属于当前范围。

根据对 Accel-Sim、CAIS 和 DySHARP 的进一步核查，当前采用两条路线：

1. PTX execution-driven 是新 ISA、新微架构、新调度和 in-switch computing
   的主线；
2. SASS/NVBit trace 是已有 A800/H100 行为、编译器效果和硬件参数的验证线。

原因是新指令不可能由现有真实 GPU 产生 SASS trace。PTX 可以让模拟器直接
执行 proposed instruction，但 PTX 结果不能自动被解释成真实 H100 性能。

当前必须区分三层：

1. Accel-Sim/GPGPU-Sim：GPU 内部指令、warp、cache、memory timing。
2. Multi-GPU/collective semantic layer：rank、stream、collective lifecycle、
   multicast、reduction 和 compute/communication dependency。
3. BookSim transport：topology、routing、VC、buffer、flit、链路竞争和传输
   延迟。

BookSim transport 不是 NVSwitch；NVSwitch 也不是 NVLS。真实 H100/NVSwitch
校准之前，所有网络数值都只能作为 synthetic/model sanity evidence。

## 5. A800 + NVBit 真实 trace workflow

在 A800 上运行了 SDK `vectoradd`，编译目标为 `sm_80`。CUDA 程序输出：

```text
Final sum = 100000.000000; sum/n = 1.000000
```

完整 workflow 已实际跑通：

```text
CUDA vectoradd
→ NVBit tracer
→ raw compressed trace
→ trace post-processing
→ .tracez + kernelslist.g
→ Accel-Sim SM80 replay
```

结果：

- raw trace：约 271 KB。
- `.tracez`：约 1.08 MB。
- kernel：98 CTAs，1,024 threads/CTA。
- Accel-Sim replay：exit 0。
- simulated cycles：6,824。
- simulated instructions：1,502,112。
- request/reply packets：各 75,000。
- CPU simulation time：约 16 秒。

这些结果证明的是 A800 software pipeline，不能转述为 H100 或 NVLink 性能。

## 6. 一条真实 trace 指令的源码 autopsy

真实记录来自：

`/tmp/in-switch-a800-trace-20260919/traces/kernel-1-ctx_0x55fde6cbb7c0.trace.xz`

代表性记录：

```text
48 0 0 17 0 0 0 0 0 0 0 00a0 ffffffff 1 R4 LDG.E.64 1 R4 8 1 0x7f7490524700 8 0 0 0 NoVal
```

已经从源码追踪到：

```text
NVBit inject_funcs.cu
→ tracer_tool.cu 写出 CTA/warp/PC/mask/opcode/address
→ post-traces-processing.cpp 生成 tracez
→ trace_parser.cc / TracezReader
→ inst_trace_t::parse_from_string
→ trace_shd_warp_t::get_next_trace_inst
→ trace_warp_inst_t::parse_from_trace_struct
→ func_exec_inst
→ warp_inst_t::generate_mem_accesses
→ simt_core_cluster::icnt_inject_request_packet
→ icnt_push
→ cache/L2/DRAM
→ icnt_pop
→ pipeline/barrier/store/scoreboard completion gate
```

该指令的 `ffffffff` mask 表示 32 个 lane 都 active/predicated；`LDG.E.64`
是 8-byte global load，地址采用 base+stride，base 为
`0x7f7490524700`、stride 为 8。trace parser 将 SASS `R4` 映射为 simulator
寄存器索引 `R5`，因为 GPGPU-Sim 保留了 register zero。

这证明 compute trace 如何进入 GPU memory timing；它不包含 rank、NCCL
collective lifecycle、peer GPU、NVSwitch queue 或 NVLS reduction。

## 7. H100/multi-GPU/NVLS gap

当前源代码审计没有证明以下能力已经存在：

| 能力 | 当前状态 |
|---|---|
| SM90/Hopper instruction/config support | 已有部分支持，需逐项审计 |
| A800 real trace generation/replay | Verified |
| multi-GPU trace with rank/device metadata | 未建立 |
| multi-GPU simulation | 未实现为本项目目标路径 |
| GPU-to-GPU NVLink timing | 未发现 |
| NVSwitch topology/queue model | 未发现 |
| NCCL collective lifecycle | 未实现 |
| `multimem` / NVLS reduction timing | 未发现 `multimem` simulator symbols |

因此不能把“一份 single-GPU trace 复制八次”称为真实 8-GPU execution。
缺失的信息至少包括 rank、peer、collective algorithm、message partition、
dependency、synchronization、topology、traffic contention 和 switch-side
reduction。

当前设计决定是：PTX workload 负责提出和执行新设计；真实 SASS trace 负责
验证已有硬件；未来通信使用独立 communication event model 或 Multi-GPU
orchestrator，不立即把所有通信语义塞进 SASS trace format。

## 8. BookSim 两 logical GPU prototype

外部 BookSim checkout 固定在 SHA `28f4329`。没有复制源码，也没有把它声明
为 Accel-Sim submodule。prototype 位于：

`tools/booksim_nvlink/`

当前 AnyNet topology 用两个 router 表示两个 logical GPU endpoint，
`bitcomp` traffic 在两个方向发送 packet。已经完成：

- standalone build。
- two-node connectivity smoke test。
- link latency 1/4/8 cycles sweep。
- packet size 1/4/16 flits sweep。
- 9 组 sweep CSV。

结果表明 BookSim 可以作为 generic two-endpoint transport timing engine。
但其参数仍是 synthetic，不是物理 NVLink calibration。

## 9. endpoint/clock contract

当前定义的未来 adapter API 是：

```text
create_network(config, endpoint_count)
inject_message(src, dst, bytes, tag, ready_time_ps)
advance_to(time_ps)
poll_completed()
read_stats()
```

推荐使用 integer picosecond global time 和 rational GPU/network clock period。
BookSim 只负责 flit transport；collective、multicast、reduction 和 NVSwitch
semantic layer 在上层。

由于外部 BookSim `TrafficManager` 的 `_Step`、injection 和 completion
队列受到 protected 访问限制，standalone `Run()` 不能直接充当嵌入式
per-event adapter。下一步需要一个最小、可追踪的 facade；目前还没有修改
BookSim 或 Accel-Sim 核心。

同时新增了 dependency-free reference contract：

- `transport_contract.py`：bytes/flits、rational clock、completion model。
- `test_transport_contract.py`：3 个 unit tests。
- `check_nvlink2_analytical.py`：9 组 BookSim sweep 的 bytes/flits/bandwidth
  sanity check。

测试结果：contract unit tests `3 tests, OK`；analytical checker
`ANALYTICAL_CHECK_PASS rows=9`。

## 12. 下一步路线

按风险从低到高：

1. 在 BookSim 外部 checkout 上实现一个最小、upstream-tracked 的 per-cycle
   facade，不改变 Accel-Sim 核心。
2. 将两个 logical GPU endpoint 的一个 timestamped message 接入 facade。
3. 用 analytical checker 验证 bytes、flits、completion ordering 和 clock
   conversion。
4. 建立 Ring AllReduce baseline，先支持 2/4/8 logical GPU。
5. 增加 NVSwitch topology/port/link/queue semantics。
6. 增加 NVLS multicast/reduction completion semantics。
7. 加入 compute + communication overlap 和 statistics。
8. 获得 H100 NVSwitch 系统后，用 nccl-tests Ring/NVLS 做 calibration。

下一阶段仍然不应该直接实现完整 NCCL、完整 NVSwitch 或跨节点通信。
