## 目标与已确定的取舍

尽快让已经提取的九个单卡 MoE workload 在 PTX 周期级模式下运行，产生正确结果，并能估算真实 GPU 的执行性能。当前范围由 `workloads/moe/docs/execution-requirements.md` 和 `workloads/moe/docs/ptx-instructions.md` 共同确定。

性能测算是模拟器的用途。计算、搬运、依赖等待和异步重叠等主要时序机制应随功能一起实现，在各阶段检查，避免全部跑通后再集中返工。允许合理近似；当前优先跑通 workload，后续有需要再提高精度。

用户已确定：
- 同时关注每个 workload 的可比设备耗时和主要耗时内核，避免不同内核的大偏差相互抵消；小内核用于辅助定位。
- 以相对真实 GPU 约 **20% 的耗时误差**作为初期可接受目标，暂不追求论文中的 10% 或完全精确模拟。主要耗时内核也按这一目标观察，不要求每个小内核、每项计数都达到相同精度。
- 明显影响性能判断的建模问题在对应阶段处理；小偏差、低影响问题记录后继续推进，不为各种 corner case 编写防御性补丁，也不为刚好压到阈值以下反复调参。
- 20% 指性能误差；数值正确性使用 workload 现有比较规则。

## 前置问题与指令分组

把 `execution-requirements.md` 的全部问题纳入计划，说明各自影响哪些运行步骤、测试或后续能力，并安排在消费者之前解决。包括 PTX 加载与语法、主机启动接口和动态共享内存、tensor map、寄存器容量和数据依赖、cluster 及异步完成等。

阻止加载、启动或基础测试的问题先处理；仅影响某个能力组的问题放到该组之前。让不受影响的分支尽早形成可运行成果。

按共用组件和真实依赖组织指令，给出能力分组及简洁依赖图。每条关键依赖解释清楚：后面的能力需要前面提供什么状态或行为。阶段顺序由这些依赖和能解锁的真实内核决定，不按指令表逐条实现。

例如，cluster/DSMEM 提供同一 cluster 内 CTA 之间的共享内存访问；使用跨 CTA 地址或共享状态的指令，应在这项能力具备后实现。普通异步拷贝、mbarrier、TMA/tensor map、矩阵存取、WGMMA 等如何分组，由实际共享机制和依赖决定。

## 阶段与验证

每个阶段都应产生可以在模拟器上运行和检查的能力。根据依赖合理拆分，避免只有解析成果的长阶段，也避免把全部 Hopper 能力打成一个大阶段。

每阶段写清：
1. 解决什么问题、为什么此时做，以及前置依赖。
2. 覆盖的指令或接口、共用组件、复用位置和最小修改范围。
3. 完成后可运行什么、能解锁哪些真实内核。
4. 最小测试、预期结果、相关时序观测及通过条件。

使用包含目标 PTX 的最小 CUDA 程序检查计算、同步和访存顺序，再用必要的指令组合与代表性真实内核检查协作和时间行为。测试应能在本阶段已有能力下执行，按 `AGENTS.md` 确认模拟库、执行模式和配置。

在涉及异步操作的阶段，检查搬运或计算何时发起、何时完成、何时允许消费和复用数据，以及能否发生预期重叠。漏算搬运、提前解除等待或错误串行化会直接影响性能，应在这里解决。延迟、吞吐等参数在代表性内核具备后及时做必要校准。

阶段验证覆盖当前需求和受影响行为即可。阻止执行、导致数值比较失败、错误同步或造成明显时序失真的问题需要处理；其余小问题简要记录触发条件、影响和暂缓原因，继续后续工作。通过必要检查后停止扩测。

给出从最小测试、代表性内核、首个完整用例到全部九个用例的推进路线，并说明首个用例的选择依据。

## 性能对比与停止条件

利用已有 H100 结果、逐调用耗时和硬件计数，设计贯穿阶段的比较方法。按同一计时范围计算相对误差：`abs(T_sim - T_ref) / T_ref`。逐用例展示整体误差，同时检查主要耗时内核，保留偏快或偏慢的方向。

按 `performance.md` 对齐比较口径：设备执行时间与主机提交间隙分开解释，周期按相应时钟换算；访存和 Tensor 工作量用于定位大的耗时差异。整体计时范围可比后再使用约 20% 的目标，避免为解释主机间隙而调整设备指令延迟。

明显超出目标时，优先查找能解释主要差额的少数原因，修正后检查受影响用例。允许记录小幅超限和低影响近似，不把每一项偏差都变成一个修补任务。完整输出通过比较、主要时序机制合理、整体及主要内核的耗时已接近初期目标后，停止本轮精调；进一步提高精度作为后续任务。
