# 阶段 7 实现方案：真实专家调用、完整前向与九例性能

本文件是待执行方案，九例当前均没有模拟运行结果。[配套验收](../validation/stage-7.md)。依赖阶段 0～6 当前消费者能力；TMA 与 WGMMA 的首次小型联测已在阶段 5/6 提前进行，不等到这里才接两条开发依赖线。

## 完成后应当能做什么

原冻结二进制在 PTX 周期模式下完成九例单卡、单层 MoE 前向，输出通过原数值标准，并给出每例内核总时间和主要内核的时间估计。首次代表性真实专家调用就测本机模拟墙钟和内存，及时判断剩余九例要跑多久。

专家 FC1/FC2 共用模块 16，每次前向调用两次；矩阵尺寸和地址由每次参数决定。不是实现九套专家算法，也不能因为同一段代码在一例通过，就省掉其它八例输出验收。

```text
全部 110 模块加载、tensor map 编码
  → 转换/gating/top-k/计数重排
  → FC1 → 激活与相关处理 → FC2 → 合并输出
  → 全量数值比较 + 按调用位置比较时间
```

“模块”是一份 PTX 编译单元；本 workload 每份含一个内核 entry。110 是九例去重后的集合，一次前向只启动其中 22～24 次。加载成功和每个内核真的执行成功是两个检查。

## 1. 在原启动路径验证完整加载与调用归属

在已有运行入口上加载原 `moe_layer` 和该用例 `forward.bin`，不重编冻结程序、不删除模块、不改 entry。利用阶段 0 的模块/函数注册信息输出一次简短登记表：模块身份、entry、host marker 对应关系；确认完整 110 模块均登记，再按前向实际调用顺序检查参数和资源归属。

同一模块的 FC1/FC2 分别保留本次参数、grid/block/cluster、dynamic shared 和输入地址；entry 相同不意味着共用同一个可变 launch 对象。这里是核查要求，不能因为用了共享符号表就先认定已有覆盖错误。

正式性能运行保留每次 launch 一行摘要即可，不开全量逐指令日志。原 `run.py` 已检查冻结二进制/输入散列及 `libcudart` 归属，直接复用，不再建一个绕过这些检查的正式启动器。

<a id="expert"></a>

## 2. 先让原专家模块的 FC1/FC2 有可独立解释的结果

专家 grouped GEMM 的含义是多个专家各算自己的矩阵，组内行数可不同。不能把所有 token 当作一张连续矩阵直接乘一次，就认为得到了该内核的参考输出。

### 输入与 ABI 的具体处理

复用阶段 0 的单模块入口，使用原模块 16、1344B/64B 对齐参数对象以及当前 grid/block/cluster/shared。先把参数表中实际用到的字段解释成：各专家输入/权重/输出地址，M/N/K 与步长，行数/分组信息，tensor map 及其修改来源。字段偏移来自冻结 PTX 的 `ld.param` 和主机输入构造；保存成该测试的参数表，不能猜结构体布局或按宿主 C++ 默认对齐重建。

优先选择 Qwen64/128 对应合法形状，用简单可计算值准备输入，保留原专家分组和 tile 工作分配。若使用更小合法形状，只将它标为功能检查，不与冻结调用的硬件时间比较。真实完整前缀可运行后，可在一次诊断运行中捕获 FC1/FC2 的实际输入与参数，用于更接近真实数据的参考计算。

### 独立预期与定位

对每个专家 e 和有效输出行 m、列 n，独立计算 `C_e[m,n]=Σ_k A_e[m,k]*B_e[k,n]`，按原模块实际输出类型和位置执行 BF16 舍入；不把中途每个乘加都先舍入到 BF16。是否读初始输出、如何处理填充行及最终写回范围，以真实指令和参数为准，并在参数表写明，不能默认为整块任意地址均有效。

CPU 参考按块处理以控制内存；不调用模拟器 WGMMA/TMA 的布局函数，不把整个大模型权重复制多份。先用可精确表示的小整数确认寻址与分组，再在实际有限值下使用既定数值规则。若原始 grouped GEMM 中间输出本身未过，先定位该调用；不能等待最终合并后用总容差掩盖它。

正常推进只保留必要结果。若完整前向失败，再在失败附近临时导出路由/行映射、FC1、激活或 FC2 的相关数据，沿调用顺序找第一处分歧；不默认给九例所有内核生成永久全量中间快照。

**SASS 复用：**可使用已有 tile/流量/资源统计帮助解释工作量；SASS 不提供独立数值参考，不能替代上述 CPU 与真实输入比较。

<a id="completion"></a>

## 3. 检查实际流水的完成点和缓存前序

原专家调用应形成以下合法顺序：TMA 输入实际写到 shared → 对应 mbarrier 满足 → WGMMA 读取/计算 → 结果完成 → 转 BF16/stmatrix → TMA 输出。生产者和消费者通过各自的 wait 复用缓冲；TMA 输出的 read wait 只保证 shared 源已经读完，最终 global 确认还须参与 kernel 完成判断。

复用前面阶段已有的动态操作 ID 和少量事件记录，确认此顺序在真实双 CTA、组播、多个 buffer 轮次里成立。四类对象必须可区分：普通 cp.async 组、TMA bulk 输出组、WGMMA 组和 mbarrier 阶段。不能用同一“异步全部完成”布尔值强迫它们一起等。

内核结束由最后必要执行/访存完成决定，不仅是所有线程到 ret。若发现遗漏，应在对应完成回调/对象所有权处修正，不能在每个 kernel 末尾加一段固定延迟代偿。

完整前向沿原初始化和前序 kernel 访问产生缓存状态，不为贴近某一基线强制每核清缓存。诊断抓取、额外同步关闭后才记正式时间。保持已确认的显式 CUDA copy 正确性、顺序和缓存影响；当前没有完整 DMA 引擎时如实单列，不把其未知时间填为零实测。

**SASS 复用：**缓存、DRAM、寄存器和 shared bank、GMMA、已接通的完成事件继续复用；本阶段检查它们在真实 PTX 数据流中的连接，不再创建第二套性能执行器。

<a id="timing"></a>

## 4. 逐内核记录时间，先解释差额再调参数

每次调用用 `launch_index、module/entry、grid/block/cluster/shared` 匹配已有硬件记录。FC1 和 FC2 必须分行，即使 entry 一样。正式摘要至少有设备开始周期、最后必要完成周期、周期差、核心频率、毫秒、逻辑矩阵工作量和主要访存字节。

优先复用已有 kernel 起止统计；若它包含纯 launch 排队时间，就在首个 CTA 开始设备执行、最后必要操作完成处补两个时间戳。统一使用设备全局周期基准，不能把各 SM 周期相加当 kernel 时长。保留核内 CTA 等待资源和流水等待；只排除核执行之外的主机提交/纯 launch 空档。

转换为 `ms=(end_cycle-start_cycle)/core_MHz/1000`。计算有符号相对误差 `(sim_ms/reference_ms)-1`，同时看内核总和、FC1/FC2/gating，以及占参考总时间 ≥5% 或能解释主要差额的调用。总和接近不能掩盖 FC1 偏高、FC2 偏低的抵消。

出现主要差额，按以下顺序处理：

1. **工作量：**逻辑 WGMMA 数×262144、有效行与填充 tile 是否一致，有无漏算或把四 warp 重复算四次。硬件 tensor math ops 可辅助比较，PTX/SASS 指令条数不直接相等。
2. **数据量：**区分逻辑 tile 字节、组播目标 shared 字节、L2 扇区与 DRAM 字节；组播两个目标不必产生两倍 DRAM 读取，缓存命中也会改变两层比例。
3. **完成与重叠：**检查轮询、mbarrier、三类 wait、配额和 shared 复用；不得先调低延迟去掩盖强制串行或错误等待。
4. **资源参数：**上述正确后，才调整有证据的延迟/发起间隔或服务吞吐。共用参数跨用例使用，不按模型/token 名字附加缩放系数。

九例初期参照是 ncu 逐内核时间，保留采集条件；三个 4096 用例再用 nsys 交叉检查。参考数值只维护在[性能概览](../hopper-validation.md#性能比较的口径)，这里不复制另一份表。自然运行完整设备时间仍留后续，CUDA event 不直接当纯 kernel 时间。

## 5. 用实际进度更新九例运行预算

第一次有代表性真实专家调用就分别记录加载/初始化、该调用模拟墙钟和峰值 RSS。Qwen64/128 完整通过后得出第一次完整前向预算，Qwen64/4096 后再修正长流水、tile 数和轮询成本。此处墙钟是本机花的时间，与模型预测 GPU 毫秒分开。

按内核类别估计剩余量：同类实际 `墙钟/设备周期` 或 `墙钟/逻辑 tile` × 剩余工作量，加每例初始化、比较和必要重跑成本。列出样本尺寸和假设；有多个有效样本就给区间，不能将一个小 WGMMA 的比例乘全部九例后写成保证。

若速度实际阻塞验收，再用一次代表性运行定位 CPU 矩阵功能计算、逐周期推进或日志的占比，针对主耗时处理；不提前引入大规模优化或假定开更多进程就能提速。九例默认逐进程顺序运行，256GB 内存允许保存必要状态，但仍记录 RSS，及时释放已不用的 tile/输出副本。

## 推进、暂缓与实际交付

顺序为 Qwen64/128 → Qwen64/4096 → Phi/128、Mixtral/128 → Phi/4096、Mixtral/4096 → 三个 8192。每例一次无预热前向，保存完整输出；改动共用语义后重跑受影响的已通过证据，不无故重复所有微测。

暂缓额外物理 bank 重分配、精细 eviction hint、通用 GPC 拓扑、完整 DMA 引擎等低影响范围。漏结果、错误寻址/同步、强制串行化或明显主要时间失真不能以“快速跑通”忽略。小幅时间超限和低影响近似注明影响与重开条件，达到初期目标就停止精调。
