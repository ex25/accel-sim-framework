# 阶段 7：真实专家 GEMM、完整前向与九例

状态：仅方案；本轮无实现、修复或运行验收。[对应验收](../validation/stage-7.md)。依赖阶段 0～6 当前消费者能力；首次 TMA/WGMMA 联测已前移，不留到本阶段。

## 本阶段做什么

把前面已分别验证的加载、路由、搬运和矩阵计算用于冻结程序。九例共用同一个专家 GEMM 模块，每次调用两次，分别做 FC1 和 FC2；不需要实现九套矩阵内核。本阶段要证明完整组合正确，并用实际主要调用校准性能。

## 当前事实、影响及指令归属

| 当前事实 | 意味着什么 |
| --- | --- |
| 启动器先编码 tensor map，再注册全部 110 模块 | 完整程序不能在缺这些能力时声称已经跑通“前几个普通内核”；此前单模块结果不等于完整程序前缀 |
| 已有九例完整 golden，没有逐内核中间 golden | 最终能直接比较，但定位 FC1/FC2 需独立小输入或取得该次真实输入后计算预期 |
| SASS 等待分派使用最近组类型 | 三类 PTX wait 要按明确 opcode/队列执行；此前各阶段分别接通，这里验证交错时不互相干扰 |
| 没有模拟墙钟与 RSS 基线 | 首个代表性专家调用就更新运行预算，不能等九例结束才知道大用例太慢 |

本阶段原则上不新增 opcode。验证阶段 0 的启动/参数、阶段 1 的基础指令、阶段 2 普通 cp.async、阶段 3/4 cluster/mbarrier、阶段 5 TMA、阶段 6 矩阵/配额的组合，以及其余现有指令的真实消费者。新发现的缺口回写所属阶段，写明触发 PTX、影响和修正，不另建“阶段 7 特判”堆补丁。

## 如何集成

1. **完整加载。** 能力语法随各阶段补齐后检查全部模块；这里运行原二进制确认 110 次注册、host marker→entry 和资源归属。不同模块的参数不串，FC1/FC2 即使 entry 相同也保存各自 launch 和输入。日志可汇总 entry/资源，不要求保存巨量逐指令日志。
2. **真实专家单独检查。** 使用模块 16 的原 PTX 和合法 ABI 构造可计算输入，或在完整程序前缀已能执行后抓取 FC1/FC2 输入。直接 CPU 分块乘法/独立参考计算输出，保留实际 BF16 舍入位置，不调用模拟器 WGMMA 布局函数来生成预期。固定形状/工作分配不能任意缩小；若只做小合法调用，性能比较不对标冻结大调用。
3. **组合完成与退出。** 验证 TMA 输入→mbarrier→WGMMA→BF16 转换/stmatrix→TMA 输出。三类异步组各自等待；内核完成保留最终写回确认，不能仅以所有线程到达 ret 判断设备工作结束。这里修正组合处有证据的遗漏，不把单项完成语义拖到最后实现。
4. **完整前向按固定顺序推进。** Qwen64/128 → Qwen64/4096 → Phi/128、Mixtral/128 → Phi/4096、Mixtral/4096 → Qwen64/8192、Phi/8192、Mixtral/8192。首例失败先定位第一处分歧；通过后用 4096 检查规模与 nsys 参照。每例独立进程、一次无预热前向。
5. **保留正确缓存前序。** 初始内存和先前内核由原程序产生；不要为使小测接近基线强制每个 kernel 冷缓存。定位用的抓取/额外同步在正式性能测量时关闭。
6. **先解释差额再调参。** 在同一提交/配置上按 launch index 匹配 FC1、FC2、gating 等：先查 math ops、地址/字节和组播量，再看等待与重叠，最后调整有证据的延迟/吞吐。不能按模型名字或 token 数加经验缩放系数凑九例。

## 时间模型复用与性能口径

复用 SASS 已有缓存/DRAM、bank、GMMA 执行资源及相关硬件统计解释；不把 SASS 动态指令数当 PTX 动态指令数，不将 SASS 通过当作本阶段验收。

主要比较同批 kernel 时间和与各主要调用，初期约 20%。九例 ncu 是有采集条件限制的参照，三个 4096 再用 nsys 交叉检查；保持[原性能表和计算口径](../hopper-validation.md#性能比较的口径)。包含主机间隙的 event、不完整 DMA 时间不能用来直接调 GPU 指令延迟。

首次真实专家结果出来就记录初始化/模拟/比较墙钟和 RSS，用[预算规则](../validation/README.md)更新九例时间预期。若实际速度阻塞交付，再定位 CPU 数值计算、逐周期推进或日志等真实开销；不预先发起广泛优化。

## 暂缓与完成边界

保留既定低影响近似：额外寄存器物理 bank 重分配、精细 eviction hint、通用 GPC 拓扑、完整显式 DMA 引擎。九例输出必须通过；漏结果、错地址、提前放行、强制串行化和明显主要时间失真不能暂缓。其余小差额记录受影响调用和原因，达到初期目标后停止精调，不扩 H200、多卡或完整 PTX ISA。
